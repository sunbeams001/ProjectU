# 页码映射机制使用指南

> 📅 创建日期: 2026-01-04  
> 🎯 目标: 说明如何使用"一层 Pager + 页码映射"公共代码  
> 📁 代码位置: `composeApp/src/commonMain/kotlin/com/projectu/ui/components/PagedNavigationHelper.kt`

---

## 📚 概述

**页码映射机制**是为双层导航页面设计的通用解决方案，通过单一 `HorizontalPager` + 页码映射算法实现流畅的滑动体验。

### 核心优势

- ✅ **滑动流畅**：无嵌套冲突，左右滑动顺序浏览所有页面
- ✅ **实现简单**：只需维护一个 Pager 状态
- ✅ **易于维护**：页码映射逻辑集中，便于理解和修改
- ✅ **性能优异**：内存占用更少，渲染开销更小

## 🧩 核心组件

### 1. PageMapping 接口

描述页面映射信息的接口：

```kotlin
interface PageMapping {
    val primaryIndex: Int        // 第一层导航索引
    val secondaryIndex: Int      // 第二层导航索引
    val showSecondaryNav: Boolean // 是否显示第二层导航
}
```

### 2. PageIndexMapper 接口

管理页码映射的核心接口：

```kotlin
interface PageIndexMapper<T : PageMapping> {
    val totalPages: Int  // 总页数
    
    // 反向映射：页码 → 页面信息
    fun parsePageIndex(pageIndex: Int): T
    
    // 正向映射：(第一层索引, 第二层索引) → 页码
    fun calculatePageIndex(primaryIndex: Int, secondaryIndex: Int): Int
}
```

### 3. PagedNavigationState 类

封装页码导航状态和操作：

```kotlin
class PagedNavigationState<T : PageMapping>(
    val pagerState: PagerState,
    val mapper: PageIndexMapper<T>
) {
    val currentMapping: T  // 当前页面的映射信息（自动计算）
    
    // 处理第一层导航点击
    fun handlePrimaryClick(...)
    
    // 处理第二层导航点击
    fun handleSecondaryClick(...)
}
```

## 🛠️ 使用方式

### 方式一：SimpleTwoLayerMapper（推荐）

适用于**简单场景**：第一个主分类无第二层导航，其他主分类有固定数量的第二层导航。

#### 示例：发现页面

**页面结构**：
```
用户(0) → 插画×3(1-3) → 小说×3(4-6)
```

**实现代码**：

```kotlin
@OptIn(ExperimentalFoundationApi::class)
@Composable
fun DiscoveryContent() {
    // 1. 定义自己的 PageMapping 实现
    data class DiscoveryPageMapping(
        override val primaryIndex: Int,
        override val secondaryIndex: Int,
        override val showSecondaryNav: Boolean,
        val contentType: DiscoveryContentType,  // 自定义字段
        val mode: DiscoveryMode?                // 自定义字段
    ) : PageMapping
    
    // 2. 创建映射器
    val contentTypes = remember { DiscoveryContentType.getAll() }
    val modes = remember { DiscoveryMode.entries }
    
    val mapper = remember {
        SimpleTwoLayerMapper(
            primaryCount = contentTypes.size,     // 3个主分类
            secondaryCount = modes.size,          // 3个模式
            firstHasSecondary = false             // 第一个主分类（用户）无第二层
        ) { primaryIndex, secondaryIndex, showSecondary ->
            val contentType = contentTypes[primaryIndex]
            val mode = if (showSecondary) modes[secondaryIndex] else null
            DiscoveryPageMapping(primaryIndex, secondaryIndex, showSecondary, contentType, mode)
        }
    }
    
    // 3. 创建 Pager 状态
    val pagerState = rememberPagerState(
        initialPage = 0,
        pageCount = { mapper.totalPages }  // 自动计算总页数 = 7
    )
    
    // 4. 创建页码导航状态
    val navState = rememberPagedNavigationState(pagerState, mapper)
    val coroutineScope = rememberCoroutineScope()
    
    Column {
        // 5. 使用 TabbedNavigationBar
        val currentMapping = navState.currentMapping
        
        TabbedNavigationBar(
            primaryItems = contentTypes,
            primarySelectedIndex = currentMapping.primaryIndex,
            onPrimaryItemClick = { index ->
                navState.handlePrimaryClick(
                    primaryIndex = index,
                    currentSecondaryIndex = currentMapping.secondaryIndex,
                    scope = coroutineScope,
                    onSamePage = { /* 刷新或滚动到顶部 */ }
                )
            },
            getPrimaryItemLabel = { /* ... */ },
            secondaryItems = modes,
            secondarySelectedIndex = currentMapping.secondaryIndex,
            onSecondaryItemClick = { index ->
                navState.handleSecondaryClick(
                    secondaryIndex = index,
                    currentPrimaryIndex = currentMapping.primaryIndex,
                    scope = coroutineScope,
                    onSamePage = { /* 刷新或滚动到顶部 */ }
                )
            },
            getSecondaryItemLabel = { /* ... */ },
            showSecondaryNav = currentMapping.showSecondaryNav
        )
        
        // 6. 单一 HorizontalPager
        HorizontalPager(
            state = pagerState,
            modifier = Modifier.fillMaxSize()
        ) { page ->
            val mapping = mapper.parsePageIndex(page)
            
            when (mapping.contentType) {
                DiscoveryContentType.USERS -> UsersPage()
                DiscoveryContentType.ILLUSTS -> IllustsPage(mode = mapping.mode!!)
                DiscoveryContentType.NOVELS -> NovelsPage(mode = mapping.mode!!)
            }
        }
    }
}
```

### 方式二：CustomTwoLayerMapper

适用于**复杂场景**：不同主分类有不同数量的第二层导航。

#### 示例：排行榜页面

**页面结构**：
```
综合×7 → 插画×6 → 动图×6 → 漫画×6 → 小说×6
```

**实现代码**：

```kotlin
@Composable
fun RankingContent() {
    // 1. 定义映射信息
    data class RankingPageMapping(
        override val primaryIndex: Int,
        override val secondaryIndex: Int,
        override val showSecondaryNav: Boolean,
        val contentType: RankingContentType,
        val mode: RankingMode
    ) : PageMapping
    
    // 2. 创建自定义映射器
    val contentTypes = remember { RankingContentType.entries }
    val modesPerType = remember {
        listOf(
            RankingMode.getAllModesFor(RankingContentType.ALL),      // 7个
            RankingMode.getAllModesFor(RankingContentType.ILLUST),   // 6个
            RankingMode.getAllModesFor(RankingContentType.UGOIRA),   // 6个
            RankingMode.getAllModesFor(RankingContentType.MANGA),    // 6个
            RankingMode.getAllModesFor(RankingContentType.NOVEL)     // 6个
        )
    }
    
    val mapper = remember {
        CustomTwoLayerMapper(
            secondaryCountPerPrimary = modesPerType.map { it.size },
            createMapping = { primaryIndex, secondaryIndex, showSecondary ->
                val contentType = contentTypes[primaryIndex]
                val mode = modesPerType[primaryIndex][secondaryIndex]
                RankingPageMapping(primaryIndex, secondaryIndex, showSecondary, contentType, mode)
            }
        )
    }
    
    // 3-6. 后续步骤与 SimpleTwoLayerMapper 相同
    // ...
}
```

## 🎯 最佳实践

### 1. 状态同步

如果 ViewModel 有自己的状态需要同步，在页面切换时更新：

```kotlin
LaunchedEffect(pagerState.currentPage) {
    val mapping = mapper.parsePageIndex(pagerState.currentPage)
    
    // 同步 ViewModel 状态
    when (mapping.contentType) {
        TypeA -> viewModelA.switchMode(mapping.mode)
        TypeB -> viewModelB.switchMode(mapping.mode)
    }
}
```

### 2. 列表状态管理

为每个页面独立维护滚动状态：

```kotlin
val listStates = remember { mutableStateMapOf<String, Any>() }

HorizontalPager(...) { page ->
    val pageKey = "page_$page"
    val listState = rememberLazyListState()
    
    LaunchedEffect(pageKey) {
        listStates[pageKey] = listState
    }
    
    // 使用 listState
}
```

### 3. 初始页面计算

如果需要根据上次状态恢复初始页面：

```kotlin
// 假设上次在"插画-SAFE"页面
val lastContentTypeIndex = 1  // 插画
val lastModeIndex = 1          // SAFE

val initialPage = mapper.calculatePageIndex(
    primaryIndex = lastContentTypeIndex,
    secondaryIndex = lastModeIndex
)

val pagerState = rememberPagerState(
    initialPage = initialPage,
    pageCount = { mapper.totalPages }
)
```

## 📖 实际案例

### 已实现页面

- ✅ **发现页面** (`DiscoveryContent.kt`) - 使用 `SimpleTwoLayerMapper`
  - 结构：用户(1页) + 插画(3页) + 小说(3页) = 7页
  - 第一个主分类无第二层导航

### 各页面适用性分析

根据[双层导航优化方案](./双层导航优化方案.md)的详细分析，以下是各页面使用 PagedNavigationHelper 的适用性评估：

#### 1. ✅ 动态页面 (FollowLatestContent) - **完全适用**

**推荐方案**: `SimpleTwoLayerMapper`

**页面结构**:
```
插画-公开(0) → 插画-私密(1) → 小说-公开(2) → 小说-私密(3)
总计：2个内容类型 × 2个关注模式 = 4页
```

**实现方式**:
```kotlin
val mapper = SimpleTwoLayerMapper(
    primaryCount = 2,        // 插画、小说
    secondaryCount = 2,      // 公开、私密
    firstHasSecondary = true // 两个内容类型都有关注模式
) { primary, secondary, showSecondary ->
    FollowLatestPageMapping(
        primaryIndex = primary,
        secondaryIndex = secondary,
        showSecondaryNav = showSecondary,
        contentType = contentTypes[primary],
        followMode = followModes[secondary]
    )
}
```

**特殊处理**:
- ⚠️ 尾部"更多"按钮需要单独处理（不影响页码映射）
- 可考虑使用 `TabbedNavigationBar` 的 `trailingContent` 参数

**改造难度**: ⭐ (简单)

---

#### 2. ✅ 排行榜页面 (RankingContent) - **完全适用**

**推荐方案**: `CustomTwoLayerMapper`

**页面结构** (动态变化):
```
根据 RankingContentModeConfig.kt，每个内容类型支持的排行模式数量各不相同：
综合 (ALL): 16个模式
插画 (ILLUST): 7个模式
动图 (UGOIRA): 4个模式
漫画 (MANGA): 7个模式
小说 (NOVEL): 14个模式
总计：16+7+4+7+14 = 48页
```

**实现方式**:
```kotlin
val contentTypes = RankingContent.entries
val modesPerType = contentTypes.map { type ->
    RankingContentModeConfig.getSupportedModes(type)
}

val mapper = CustomTwoLayerMapper(
    secondaryCountPerPrimary = modesPerType.map { it.size }, // [16, 7, 4, 7, 14]
    createMapping = { primary, secondary, showSecondary ->
        RankingPageMapping(
            primaryIndex = primary,
            secondaryIndex = secondary,
            showSecondaryNav = showSecondary,
            contentType = contentTypes[primary],
            mode = modesPerType[primary][secondary]
        )
    }
)
```

**特殊处理**:
- ⚠️ 日期选择器需要单独处理
- 建议：使用 `TabbedNavigationBar` 时，将日期选择器作为独立组件放在导航栏外
- 或者：创建自定义布局，将日期选择器集成到 TabRow 的右侧

**改造难度**: ⭐⭐ (中等，需要处理日期选择器)

---

#### 3. ⚠️ FollowLatestMoreScreen - **部分适用，建议扁平化**

**当前结构**:
```
第1层: 追更列表 | 好P友
第2层: 漫画 | 小说 (仅在"追更列表"显示)
```

**问题分析**:
- 嵌套 Pager 结构：第1层切换大功能，第2层在"追更列表"内切换
- 第2层仅对第1层的一个选项有效，逻辑不清晰
- 用户认知成本高

**方案A**: 使用 `SimpleTwoLayerMapper` (不推荐)
```kotlin
// 页面结构：追更-漫画(0) → 追更-小说(1) → 好P友(2)
val mapper = SimpleTwoLayerMapper(
    primaryCount = 2,        // 追更列表、好P友
    secondaryCount = 2,      // 漫画、小说
    firstHasSecondary = true // 第一个有第二层
) { primary, secondary, showSecondary ->
    // 但第二个主分类（好P友）实际不需要第二层...
}
```
问题：好P友不需要第二层导航，强行使用会造成空页面

**方案B**: 扁平化重构 ⭐⭐⭐ (强烈推荐)
```kotlin
// 将三个功能作为同级 Tab，无需页码映射
enum class WatchListTab {
    MANGA,      // 追更-漫画
    NOVEL,      // 追更-小说
    FRIENDS     // 好P友
}

// 使用简单的 TabRow + HorizontalPager (3页)
// 不需要 PagedNavigationHelper
```

**推荐方案**: **扁平化重构** - 将"追更-漫画"、"追更-小说"、"好P友"作为同级 Tab
- ✅ 逻辑最清晰
- ✅ 代码最简单
- ✅ 用户最容易理解
- ✅ 无需复杂的页码映射

**改造难度**: ⭐⭐⭐ (需要重构，但结果更好)

## 💡 常见问题

### Q: 如何处理第一个主分类有第二层导航的情况？

A: 设置 `firstHasSecondary = true`：

```kotlin
SimpleTwoLayerMapper(
    primaryCount = 3,
    secondaryCount = 3,
    firstHasSecondary = true  // 所有主分类都有第二层
)
```

### Q: 如何实现三层导航？

A: 目前框架支持双层，三层可以考虑：
1. 将三层扁平化为两层
2. 第三层使用独立的 Tab 或 Dropdown

### Q: Mapper 可以动态改变吗？

A: Mapper 应该是稳定的，如果页面结构会变化，建议：
1. 使用 `remember(key)` 重新创建 Mapper
2. 或使用条件逻辑在 `createMapping` 中处理
