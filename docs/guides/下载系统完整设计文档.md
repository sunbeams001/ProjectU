## 下载路径规则系统

### 1. 设计理念

#### 核心原则

**路径管理权交给用户**：

在规则系统中，用户通过 `targetPath` + `subDirectory` + `authorGrouping` 完全控制文件存储位置。

**示例**：

```kotlin
// 内置默认规则（零配置）
DownloadRule(
    resourceTypeFilter = ILLUSTRATION,
    targetPath = "/storage/emulated/0/Pictures/ProjectU",
    subDirectory = "Illustrations",
    authorGrouping = NONE
)
// 结果：/storage/emulated/0/Pictures/ProjectU/Illustrations/123456_0.jpg

// 用户自定义规则（R-18分离）
DownloadRule(
    resourceTypeFilter = ILLUSTRATION,
    r18Filter = MUST_BE,
    targetPath = "/storage/emulated/0/Pictures/NSFW",
    subDirectory = "",  // 不添加资源类型子目录
    authorGrouping = BY_NAME
)
// 结果：/storage/emulated/0/Pictures/NSFW/ArtistName/123456_0.jpg
```

**优势**：
- 🎯 **简洁性**: 用户选择的路径就是最终位置
- 🎯 **灵活性**: 可以混合存储多种资源类型
- 🎯 **可预测**: 所见即所得

#### 规则匹配策略

1. **优先级匹配**: 从上到下遍历规则，使用第一个匹配的规则
2. **默认兜底**: 如果没有自定义规则匹配，使用内置默认规则
3. **性能优化**: 规则缓存在内存中，匹配时间 < 1ms

#### 领域模型

```kotlin
/**
 * 下载规则（领域模型）
 * 
 * 文件位置：shared/src/commonMain/kotlin/com/projectu/shared/domain/model/DownloadRule.kt
 */
data class DownloadRule(
    val id: Long = 0,
    val order: Int,                              // 优先级（值越小越高）
    val resourceTypeFilter: ResourceTypeFilter,  // 资源类型过滤
    val r18Filter: FilterType,                   // R-18过滤
    val aiFilter: FilterType,                    // AI作品过滤
    val authorGrouping: AuthorGrouping,          // 作者分组模式
    val targetPath: String,                      // 目标路径
    val enabled: Boolean = true,                 // 是否启用
    val createdAt: Long = System.currentTimeMillis(),
    val updatedAt: Long = System.currentTimeMillis(),
    val subDirectory: String = ""                // 资源类型子目录（内置规则）
) {
    /**
     * 判断任务是否匹配此规则
     */
    fun matches(task: DownloadTask): Boolean {
        // 1. 资源类型匹配
        if (resourceTypeFilter != ResourceTypeFilter.ANY) {
            val expectedType = when (resourceTypeFilter) {
                ResourceTypeFilter.ILLUSTRATION -> ResourceType.ILLUSTRATION
                ResourceTypeFilter.MANGA -> ResourceType.MANGA
                ResourceTypeFilter.UGOIRA -> ResourceType.UGOIRA
                ResourceTypeFilter.NOVEL -> ResourceType.NOVEL
                ResourceTypeFilter.NOVEL_SERIES -> ResourceType.NOVEL_SERIES
                ResourceTypeFilter.ANY -> null
            }
            if (task.resourceType != expectedType) return false
        }
        
        // 2. R-18 匹配
        when (r18Filter) {
            FilterType.MUST_BE -> if (!task.isR18) return false
            FilterType.MUST_NOT_BE -> if (task.isR18) return false
            FilterType.ANY -> { /* 不过滤 */ }
        }
        
        // 3. AI 匹配
        when (aiFilter) {
            FilterType.MUST_BE -> if (!task.isAi) return false
            FilterType.MUST_NOT_BE -> if (task.isAi) return false
            FilterType.ANY -> { /* 不过滤 */ }
        }
        
        return true
    }
    
    /**
     * 根据规则构建相对路径
     * 
     * 路径构成：subDirectory + authorGrouping
     * 
     * 示例：
     * - "Illustrations/123456" (有子目录 + 按作者ID)
     * - "ArtistName" (无子目录 + 按作者名)
     * - "" (都不启用)
     */
    fun buildRelativePath(task: DownloadTask): String {
        val authorPath = when (authorGrouping) {
            AuthorGrouping.BY_ID -> task.authorId
            AuthorGrouping.BY_NAME -> sanitizeFileName(task.authorName)
            AuthorGrouping.NONE -> ""
        }
        
        return when {
            subDirectory.isNotEmpty() && authorPath.isNotEmpty() -> "$subDirectory/$authorPath"
            subDirectory.isNotEmpty() -> subDirectory
            authorPath.isNotEmpty() -> authorPath
            else -> ""
        }
    }
}
```

### 4. 规则缓存层 ⭐

```kotlin
/**
 * 下载规则缓存
 * 
 * 文件位置：shared/src/commonMain/kotlin/com/projectu/shared/data/cache/DownloadRulesCache.kt
 * 
 * 设计目标：
 * - 避免每次下载任务都查询数据库
 * - 提供同步的规则匹配方法
 * - 自动订阅 Store 更新，保持缓存一致性
 * 
 * 性能优化：
 * - 规则列表存储在内存中（StateFlow）
 * - findMatchingRule() 时间复杂度：O(n)，n = 规则数量
 * - 规则数量限制：建议最多 20 条，实际匹配耗时 < 1ms
 */
class DownloadRulesCache(
    private val downloadRulesStore: DownloadRulesStore,
    private val baseDownloadPathProvider: () -> String
) {
    private val coroutineScope = CoroutineScope(Dispatchers.Default + SupervisorJob())
    
    private val _rules = MutableStateFlow<List<DownloadRule>>(emptyList())
    val rules: StateFlow<List<DownloadRule>> = _rules.asStateFlow()
    
    init {
        // 自动订阅数据库更新
        coroutineScope.launch {
            downloadRulesStore.rules.collect { entities ->
                _rules.value = entities.map { it.toDownloadRule() }
            }
        }
    }
    
    /**
     * 查找匹配的规则（同步方法）
     * 
     * 策略：
     * 1. 如果有自定义规则，按优先级匹配
     * 2. 如果没有匹配，使用内置默认规则
     */
    fun findMatchingRule(task: DownloadTask): DownloadRule {
        val enabledRules = _rules.value.filter { it.enabled }
        
        // 1. 遍历自定义规则
        for (rule in enabledRules) {
            if (rule.matches(task)) {
                return rule
            }
        }
        
        // 2. 使用内置默认规则
        val currentBasePath = baseDownloadPathProvider().ifEmpty { 
            DownloadRuleDefaults.DEFAULT_BASE_PATH_ANDROID 
        }
        
        val builtInRules = DownloadRuleDefaults.getBuiltInRules(currentBasePath)
        for (rule in builtInRules) {
            if (rule.matches(task)) {
                return rule
            }
        }
        
        // 理论上不应到达这里
        throw IllegalStateException("No matching rule found for task: ${task.resourceType}")
    }
}
```

## 文件命名规则系统

### 1. 命名模板系统

文件名通过 **模板替换** 机制生成，支持标准模式和自定义模式。

#### 文件命名模式

```kotlin
/**
 * 文件命名模式
 */
enum class FileNameMode {

    CUSTOM     // 自定义模式: 用户自定义模板
```

#### 智能模板处理

**核心机制**：不同资源类型自动处理 `{p}` 页码变量

- **插画/漫画**：保留 `{p}`（用于区分多页）
- **动图/小说/小说系列**：自动移除 `{p}`（永远是单文件）

**示例**：
```
标准模板: {id}_{p}_{title}

插画:       123456789_0_风景.jpg      (保留页码)
漫画P1:     123456789_0_漫画.jpg      (保留页码)
漫画P2:     123456789_1_漫画.jpg
动图:       123456789_动图.gif        (自动移除 _p_)
小说:       123456789_小说.epub       (自动移除 _p_)
小说系列:   987654321_系列.epub       (自动移除 _p_)
```

### 2. 支持的模板变量

| 变量 | 说明 | 示例值 | 备注 |
|------|------|--------|------|
| `{id}` | 作品ID | `123456789` | 必选，唯一标识 |
| `{p}` | 页码索引 | `0`, `1`, `2` ... | 从0开始，多页作品建议保留 |
| `{title}` | 作品标题 | `美丽的风景` | 自动清理非法字符 |
| `{author_id}` | 作者ID | `987654321` | |
| `{author_name}` | 作者名 | `Artist_Name` | 自动清理非法字符 |
| `{publish_date}` | 发布时间 | `2025-01-15` | 格式: yyyy-MM-dd |
| `{download_date}` | 下载时间 | `2025-12-18` | 格式: yyyy-MM-dd |
| `{ai}` | AI标识 | `AI` 或空 | AI作品显示AI，否则为空 |
| `{r18}` | R-18标识 | `R-18` 或空 | R-18作品显示R-18，否则为空 |
| `{tags}` | 标签 | `风景_自然_天空` | 最多5个标签，下划线分隔 |

#### 插画（Illustration）

**为什么保留 `_0`？**
- 单页插画的页码索引为 `pageIndex = 0`
- 与多页漫画保持命名一致性
- 如果将来作品新增页面，命名规则不变

```
第2页: 123456789_1_漫画标题.jpg
第3页: 123456789_2_漫画标题.jpg
```

**实现细节**：
- 每一页创建独立的下载任务
- `pageIndex` 从 0 开始计数（与数组索引一致）
- 通过 `{p}` 变量区分不同页面

```kotlin
fun buildFileName(task: DownloadTask, settings: DownloadSettings, extension: String = "jpg"): String {
    // 1. 根据模式获取模板
    val baseTemplate = when (settings.fileNameMode) {
        FileNameMode.STANDARD -> "{id}_{p}_{title}"
        FileNameMode.CUSTOM -> settings.customFileNameTemplate
    }
    
    // 2. 智能处理：对单文件资源移除 {p}
    val effectiveTemplate = when (task.resourceType) {
        ResourceType.UGOIRA, ResourceType.NOVEL, ResourceType.NOVEL_SERIES -> {
            baseTemplate
                .replace("_{p}_", "_")   // 中间的 _{p}_
                .replace("_{p}", "")     // 末尾的 _{p}
                .replace("{p}_", "")     // 开头的 {p}_
                .replace("{p}", "")      // 单独的 {p}
        }
        else -> baseTemplate  // 插画和漫画保持原样
    }
    
    // 3. 替换所有变量
    val fileName = effectiveTemplate
        .replace("{id}", task.resourceId)
        .replace("{p}", task.pageIndex?.toString() ?: "0")
        .replace("{title}", sanitizeFileName(task.title))
        .replace("{author_id}", task.authorId)
        .replace("{author_name}", sanitizeFileName(task.authorName))
        .replace("{publish_date}", formatDate(task.publishTime))
        .replace("{download_date}", formatDate(task.downloadTime))
        .replace("{ai}", if (task.isAi) "AI" else "")
        .replace("{r18}", if (task.isR18) "R-18" else "")
        .replace("{tags}", task.tags.take(5).joinToString("_") { sanitizeFileName(it) })
    
    // 4. 清理连续分隔符（但保留末尾单个分隔符）
    val cleanFileName = fileName
        .replace(Regex("_+"), "_")      // 合并连续下划线
        .replace(Regex("-+"), "-")      // 合并连续连字符
        .replace(Regex(" +"), " ")      // 合并连续空格
        .replace(Regex("^[_\\-\\s]+"), "")  // 移除开头分隔符
        .let { sanitizeFileName(it) }
    
    return "$cleanFileName.$extension"
}
```

#### 文件名清理

```kotlin
/**
 * 文件名合法化处理（跨平台）
 * 移除或替换 Windows/Linux/macOS 不支持的字符
 */
private fun sanitizeFileName(name: String): String {
    // 非法字符: \ / : * ? " < > | 和控制字符
    val illegalChars = Regex("""[\\/:*?"<>|\u0000-\u001F\u007F]""")
    
    return name
        .replace(illegalChars, "_")  // 替换为下划线
        .trim()                      // 去除首尾空格
        .take(200)                   // 限制长度（Windows MAX_PATH = 260）
        .ifEmpty { "untitled" }      // 避免空文件名
}

/**
 * 格式化日期（yyyy-MM-dd）
 */
private fun formatDate(timestamp: Long): String {
    val format = SimpleDateFormat("yyyy-MM-dd", Locale.getDefault())
    return format.format(Date(timestamp))
}
```

### 8. 常见问题

#### Q1: 为什么插画文件名有 `_0`，动图没有？

**A**: 系统对不同资源类型使用智能模板处理：

- **插画/漫画**：可能有多页，保留 `{p}` 用于区分（即使单页也保留以保持一致性）
- **动图/小说**：永远只有一个文件，自动移除 `{p}` 避免无意义的 `_0`

#### Q2: 页码为什么从0开始而不是从1？

**A**: 三个原因：
1. 与数组索引一致：`artwork.imageUrls.pages[0]`
2. API 返回的数据从0开始
3. 编程习惯：大多数语言数组索引从0开始

#### Q3: 多页漫画的命名规则？

**A**: 每页创建独立的下载任务，通过 `{p}` 区分：

```
作品: 123456789 "冒险漫画" (3页)

生成的文件：
- 123456789_0_冒险漫画.jpg  (第1页)
- 123456789_1_冒险漫画.jpg  (第2页)
- 123456789_2_冒险漫画.jpg  (第3页)
```

#### Q4: 自定义模板时不包含 `{p}` 会怎样？

**A**: 单页作品正常，多页作品会文件名冲突（后一页覆盖前一页）。

**建议**：始终保留 `{p}` 变量。

#### Q5: 如何自定义文件命名规则？

**A**: 通过设置界面：

1. 进入"设置" → "下载设置"
2. 点击"文件命名规则"菜单项
3. 选择"自定义模板"
4. 输入模板或使用快捷插入按钮
5. 实时预览效果
6. 保存后立即生效

```kotlin
class AndroidFileWriter(private val context: Context) : PlatformFileWriter {
    override fun createSink(path: Path, displayName: String): Sink {
        return if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q) {
            createMediaStoreSink(path, displayName)  // Android 10+
        } else {
            createLegacySink(path)  // Android 7-9
        }
    }
    
    private fun createMediaStoreSink(path: Path, displayName: String): Sink {
        val resolver = context.contentResolver
        val mimeType = getMimeType(displayName)
        val collection = getCollection(mimeType)
        
        // 使用 IS_PENDING 标志实现原子写入
        val contentValues = ContentValues().apply {
            put(MediaStore.MediaColumns.DISPLAY_NAME, displayName)
            put(MediaStore.MediaColumns.MIME_TYPE, mimeType)
            put(MediaStore.MediaColumns.RELATIVE_PATH, getRelativePath(path))
            if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q) {
                put(MediaStore.MediaColumns.IS_PENDING, 1)
            }
        }
        
        val uri = resolver.insert(collection, contentValues)!!
        return resolver.openOutputStream(uri).sink().buffer()
    }
}
```
