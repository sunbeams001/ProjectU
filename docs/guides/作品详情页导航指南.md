# 作品详情页列表导航指南

> 📅 创建日期: 2025-11-27  
> 📅 最后更新: 2025-12-01  
> 🎯 目标: 支持在作品详情页面左右滑动浏览列表中的其他作品，并支持返回列表时自动滚动到最后浏览的位置  
> 🏗️ 实现: HorizontalPager + NavigationContextManager + ArtworkListSource 接口 + 响应式 StateFlow  
> 📦 版本: v2.0

---

## 📋 功能概述

作品详情页现在支持两种导航模式：

1. **单个作品模式**：独立查看某个作品的详情
2. **列表导航模式**：在作品列表上下文中查看作品，支持左右滑动浏览列表中的其他作品

核心功能特性：

✅ **左右滑动浏览**：通过 HorizontalPager 支持流畅的左右滑动切换作品  
✅ **缓存机制**：已加载的作品数据会被缓存，瞬间显示  
✅ **预加载优化**：自动预加载相邻作品，提升浏览体验  
✅ **返回定位**：返回列表时自动滚动到最后浏览的作品位置  
✅ **平滑滚动动画**：使用 animateScrollToItem 实现平滑滚动  
✅ **加载状态明确**：切换到未缓存的作品时显示加载指示器，避免混淆  
✅ **自动加载更多**：接近列表末尾时自动触发加载更多  
✅ **响应式列表更新**：通过 ArtworkListSource 接口实现真正的响应式更新（v2.0）  
✅ **Activity 状态恢复**：支持进程被杀死后的优雅降级（v2.0）

## 🏗️ 架构设计

### 核心设计思想 (v2.0)

1. **Screen 只存储静态的、可序列化的数据**（列表快照、当前索引）

3. **状态恢复时优雅降级**：如果接口引用丢失，使用序列化的快照数据

```kotlin
@Composable
override fun Content() {
    val context = remember(contextKey) {
        if (contextKey.isNotEmpty()) NavigationContextManager.getContext(contextKey) else null
    }
    
    // 订阅列表源的 StateFlow（如果有的话）
    val liveArtworkIds by context?.listSource?.artworkIdsFlow?.collectAsState() 
        ?: remember { mutableStateOf(emptyList()) }
    
    // 优先使用 listSource 的实时数据，否则降级到序列化的快照
    val currentArtworkIds = if (liveArtworkIds.isNotEmpty()) {
        liveArtworkIds
    } else {
        artworkIds  // 降级：使用序列化的快照
    }
    
    // 初始化
    LaunchedEffect(artworkId, initialIndex) {
        if (currentArtworkIds.isNotEmpty()) {
            val onLoadMore: (() -> Unit)? = context?.listSource?.let { source ->
                { source.loadMoreArtworks() }
            }
            viewModel.initWithArtworkList(currentArtworkIds, initialIndex, onLoadMore)
        } else if (artworkId.isNotEmpty()) {
            viewModel.loadArtworkDetail(artworkId)
        }
    }
    
    // 监听列表变化，更新 ViewModel
    LaunchedEffect(currentArtworkIds.size) {
        if (currentArtworkIds.isNotEmpty()) {
            viewModel.updateArtworkList(currentArtworkIds)
        }
    }
}
```

```kotlin
private fun preloadAdjacentArtworks(currentIndex: Int) {
    // 预加载前一个作品
    if (currentIndex > 0) {
        val prevId = artworkIds[currentIndex - 1]
        if (!artworkCache.containsKey(prevId)) {
            loadArtworkDetail(prevId, silent = true)
        }
    }
    
    // 预加载后一个作品
    if (currentIndex < artworkIds.size - 1) {
        val nextId = artworkIds[currentIndex + 1]
        if (!artworkCache.containsKey(nextId)) {
            loadArtworkDetail(nextId, silent = true)
        }
    }
}
```

#### 5. ArtworkDetailContent

**核心实现**: 使用 `HorizontalPager` 实现左右滑动

```kotlin
@Composable
fun ArtworkListPager(
    state: ArtworkDetailState,
    onPageChange: (Int) -> Unit,
    modifier: Modifier = Modifier
) {
    val pagerState = rememberPagerState(
        initialPage = state.currentIndex,
        pageCount = { state.artworkIds.size }
    )
    
    // 监听页面切换
    LaunchedEffect(pagerState.currentPage, pagerState.isScrollInProgress) {
        if (!pagerState.isScrollInProgress && 
            pagerState.currentPage != state.currentIndex) {
            onPageChange(pagerState.currentPage)
        }
    }
    
    HorizontalPager(
        state = pagerState,
        modifier = modifier,
        key = { index -> state.artworkIds.getOrNull(index) ?: index }
    ) { pageIndex ->
        val artworkId = state.artworkIds.getOrNull(pageIndex) ?: return@HorizontalPager
        val cachedArtwork = state.artworkCache[artworkId]
        
        when {
            cachedArtwork != null -> {
                // 有缓存，瞬间显示
                ArtworkDetailLayout(artwork = cachedArtwork, ...)
            }
            
            pageIndex == state.currentIndex && 
            state.artwork != null && 
            state.artwork.id == artworkId -> {
                // 当前页面且作品ID匹配
                ArtworkDetailLayout(artwork = state.artwork, ...)
            }
            
            else -> {
                // 未加载或数据不匹配，显示加载指示器
                Box(modifier = Modifier.fillMaxSize()) {
                    Column(horizontalAlignment = Alignment.CenterHorizontally) {
                        CircularProgressIndicator()
                        Text("加载中...")
                    }
                }
            }
        }
    }
}
```

**关键优化点**:

1. **作品ID匹配检查**：防止显示旧作品造成混淆
   ```kotlin
   state.artwork != null && state.artwork.id == artworkId
   ```

2. **缓存优先**：优先从缓存中获取作品数据
   ```kotlin
   val cachedArtwork = state.artworkCache[artworkId]
   if (cachedArtwork != null) { /* 瞬间显示 */ }
   ```

3. **明确的加载状态**：未缓存时显示加载指示器，而不是旧内容

```kotlin
@Composable
fun RankingContent(
    state: RankingState,
    scrollIndices: MutableMap<String, Int> = mutableMapOf(),
    ...
) {
    HorizontalPager(...) { page ->
        val mode = supportedModes[page]
        
        // 为每个模式创建独立的列表状态
        val listState = rememberLazyStaggeredGridState()
        
        // 使用 derivedStateOf 建立响应式依赖
        val targetScrollIndex by remember(mode.value) {
            derivedStateOf { scrollIndices[mode.value] }
        }
        
        // 监听滚动索引变化，自动滚动
        LaunchedEffect(targetScrollIndex) {
            val scrollIndex = targetScrollIndex
            if (scrollIndex != null && scrollIndex > 0) {
                listState.scrollToItem(scrollIndex)
                scrollIndices.remove(mode.value)  // 滚动完成后清除
            }
        }
        
        // 渲染列表内容
        ArtworkStaggeredGridLayout(listState = listState, ...)
    }
}
```

**关键技术点**:

1. **scrollIndices 提升到 Tab 级别**：避免导航时丢失状态
2. **derivedStateOf 建立响应式**：Map 内容变化时触发重组
3. **LaunchedEffect 监听变化**：自动执行滚动操作
4. **滚动后清除标记**：避免重复滚动

## 🔄 工作流程

### 正常导航流程

```
1. 用户在列表页点击作品
   ↓
2. 列表页创建 ArtworkListSource（绑定到特定 mode/tab）
   ↓
3. 列表页调用 NavigationContextManager.createContext()
   - listSource = viewModel.createArtworkListSource(currentMode)
   - onReturnWithIndex = { index -> scrollIndices[key] = index }
   ↓
4. 列表页 push ArtworkDetailScreen
   - artworkIds = 当前列表快照（用于降级）
   - initialIndex = 点击的索引
   - contextKey = 创建的 key
   ↓
5. 详情页获取 context，订阅 listSource.artworkIdsFlow
   ↓
6. 用户滑动到接近末尾 → 调用 listSource.loadMoreArtworks()
   ↓
7. 源 ViewModel 加载更多 → artworkIdsFlow 自动发出新值
   ↓
8. 详情页自动获取新列表，Pager 页数增加
   ↓
9. 用户返回 → 调用 onReturnWithIndex(currentIndex)
   ↓
10. 列表页滚动到对应位置
```

### 状态恢复流程（Activity 重建）

```
1. Activity 被系统销毁
   ↓
2. Voyager 序列化 ArtworkDetailScreen
   - artworkIds: List<String> ✓ 保存成功
   - initialIndex: Int ✓ 保存成功
   - contextKey: String ✓ 保存成功
   ↓
3. Activity 重建，Voyager 恢复 Screen
   ↓
4. 详情页尝试获取 context → null（内存中的数据已丢失）
   ↓
5. 降级模式：
   - 使用序列化的 artworkIds 快照
   - 不支持加载更多（listSource 为 null）
   - 不支持返回定位（onReturnWithIndex 为 null）
   - 但仍可在已有列表中滑动浏览
```

## 💡 设计亮点

### 1. ArtworkListSource 接口 (v2.0)

**问题**:
- v1.x 中使用 `State<List<String>>` 或 `derivedStateOf`，但这些不能序列化
- 导致 Activity 恢复后功能异常
- 轮询检测列表变化不够优雅

**解决方案**:

1. **定义通用接口**:
```kotlin
interface ArtworkListSource {
    val artworkIdsFlow: StateFlow<List<String>>
    fun loadMoreArtworks()
}
```

2. **ViewModel 提供工厂方法**:
```kotlin
fun createArtworkListSource(modeKey: String): ArtworkListSource {
    return object : ArtworkListSource {
        override val artworkIdsFlow = state.map { ... }.stateIn(...)
        override fun loadMoreArtworks() = loadMore()
    }
}
```

3. **详情页订阅 StateFlow**:
```kotlin
val liveArtworkIds by context?.listSource?.artworkIdsFlow?.collectAsState()
```

**优势**:
- 真正的响应式更新（不需要轮询）
- 接口统一，详情页不需要知道具体 ViewModel 类型
- 支持多 mode/tab 场景（工厂方法绑定特定上下文）
- Activity 恢复时优雅降级

### 2. 缓存机制

**ViewModel 中的缓存**:
```kotlin
private val artworkCache = mutableMapOf<String, Artwork>()

// 加载成功后缓存
artworkCache[artworkId] = artwork

// 暴露给 UI
_state.update { it.copy(artworkCache = artworkCache.toMap()) }
```

**优势**:
- 已浏览的作品瞬间显示，无需重新加载
- 减少网络请求，节省流量
- 提升用户体验，滑动流畅

### 3. 预加载优化

**策略**:
- 加载当前作品后，自动预加载前后各一个作品
- 静默加载（silent = true），不影响 UI 状态
- 检查缓存，避免重复加载

**效果**:
- 用户滑动到相邻作品时，内容已加载完成
- 几乎零延迟的浏览体验

### 4. 明确的加载状态

**问题**:
- 旧实现中，切换到新页面时会短暂显示旧作品，造成混淆

**解决方案**:
```kotlin
when {
    cachedArtwork != null -> { /* 显示缓存的作品 */ }
    
    pageIndex == state.currentIndex && 
    state.artwork != null && 
    state.artwork.id == artworkId -> { /* 显示当前作品 */ }
    
    else -> { /* 显示加载指示器 */ }
}
```

**关键检查**: `state.artwork.id == artworkId` 确保显示的是正确的作品

### 5. 返回定位与平滑滚动

**用户痛点**:
- 返回列表后，虽然滚动到了最后浏览的作品，但用户可能看不清具体是哪个
- 瞬间跳转的滚动体验不够流畅

**解决方案**:

1. **平滑滚动动画**:
```kotlin
// 替代原来的 scrollToItem

```

2. **高亮状态管理**:
```kotlin

        // 显示高亮动画

        delay(2000) // 持续 2 秒
        highlightedIndex = null
        
        scrollIndices.remove(mode.value)

```

3. **脉冲边框动画**:

```kotlin
)

Modifier.scale(scale)
```

**视觉效果**:
- **平滑滚动**：列表优雅地滚动到目标位置，而非瞬间跳转
- **脉冲边框**：主题色边框，透明度在 0.3-1.0 之间呼吸，循环往复
- **弹性缩放**：作品轻微放大到 1.05 倍，带有弹性效果
- **自动消失**：2 秒后高亮效果自动消失，不干扰后续操作

**动画参数**:
- 脉冲周期：800ms
- 缩放比例：1.0 → 1.05（作品卡片），1.0 → 1.02（小说卡片）
- 边框宽度：3dp（作品），2dp（小说）
- 高亮时长：2000ms
- 弹性阻尼：`Spring.DampingRatioMediumBouncy`
- 弹性刚度：`Spring.StiffnessLow`

### 6. 状态提升与响应式依赖

**挑战**:
- Tab 导航会导致 Composable 重组，`remember` 状态可能丢失
- Map 内容变化不会触发 Compose 重组

**解决方案**:

1. **提升状态到 Tab 对象级别**:
```kotlin
object RankingTab : Tab {
    private val scrollIndices = mutableStateMapOf<String, Int>()
}
```

2. **使用 derivedStateOf 建立响应式依赖**:
```kotlin
val targetScrollIndex by remember(mode.value) {
    derivedStateOf { scrollIndices[mode.value] }
}
```

3. **LaunchedEffect 监听变化并滚动**:
```kotlin
LaunchedEffect(targetScrollIndex) {
    if (targetScrollIndex != null && targetScrollIndex > 0) {
        listState.scrollToItem(targetScrollIndex)
        scrollIndices.remove(mode.value)
    }
}
```

### 7. 系统返回拦截

**问题**: 用户使用系统返回键或手势返回时，`onBackClick` 不会被调用

**解决方案**: 使用 `BackHandler` 统一处理
```kotlin
val handleBack: () -> Unit = {
    val currentIndex = viewModel.getCurrentIndex()
    onReturnWithIndex?.invoke(currentIndex)
    navigator.pop()
}

BackHandler(enabled = true, onBack = handleBack)
```

### 8. 自动加载更多

**触发时机**: 距离列表末尾还有 5 个作品时
```kotlin
if (newIndex >= artworkIds.size - 5) {
    onLoadMoreCallback?.invoke()
}
```

**效果**: 用户无需手动触发，滑动到末尾附近自动加载更多内容

## 🔧 故障排查

### 常见问题

**Q: 滑动后显示的是错误的作品？**  
A: 检查 Pager 的 key 是否正确设置，确保使用作品ID而不是索引。同时检查是否有 `state.artwork.id == artworkId` 的匹配检查。

**Q: 滑动后先显示旧作品，然后才刷新？**  
A: 这是因为没有检查作品ID匹配。确保在显示作品前验证 `state.artwork.id == artworkId`。

**Q: 滑动不流畅或卡顿？**  
A: 检查是否在滑动过程中进行了重度计算，考虑使用 `derivedStateOf` 优化。检查预加载是否过度。

**Q: 返回列表后位置没有滚动？**  
A: 检查以下几点：
1. `scrollIndices` 是否提升到 Tab 对象级别
2. 是否使用了 `derivedStateOf` 建立响应式依赖
3. `onReturnWithIndex` 回调是否正确执行
4. `BackHandler` 是否正确拦截了系统返回

**Q: 系统返回键不触发 onReturnWithIndex？**  
A: 使用 `BackHandler` 统一处理按钮返回和系统返回：
```kotlin
BackHandler(enabled = true, onBack = handleBack)
```

**Q: 某些作品加载失败？**  
A: 确保错误处理逻辑完善，显示友好的错误提示和重试选项。

**Q: scrollIndices 在导航后丢失？**  
A: 将 `scrollIndices` 从 Composable 内的 `remember` 提升到 Tab 对象的属性：
```kotlin
object RankingTab : Tab {
    private val scrollIndices = mutableStateMapOf<String, Int>()
}
```

**Q: 自动加载更多不工作？**  
A: v2.0 之前的版本使用 `State<List<String>>` 或 `derivedStateOf`，这些不能序列化。v2.0 使用 `ArtworkListSource` 接口解决了这个问题。确保：
1. ViewModel 提供了 `createArtworkListSource()` 工厂方法
2. 创建 context 时传递了正确的 listSource
3. 详情页正确订阅了 `listSource.artworkIdsFlow`

**Q: Activity 恢复后功能异常？**  
A: 这是预期的降级行为。当 Activity 被系统杀死后恢复时：
- `NavigationContextManager` 中的数据会丢失
- 详情页会降级使用序列化的 `artworkIds` 快照
- 加载更多和返回定位功能不可用，但仍可在已有列表中滑动浏览

**Q: 返回列表后看不清滚动到哪个位置了？**  
A: 高亮动画效果：
- 使用 `animateScrollToItem` 替代 `scrollToItem`，实现平滑滚动
- 滚动到的作品会显示脉冲边框（主题色，透明度 0.3-1.0 呼吸效果）
- 作品会有轻微的缩放动画（1.0 → 1.05）
- 高亮效果持续 2 秒后自动消失
