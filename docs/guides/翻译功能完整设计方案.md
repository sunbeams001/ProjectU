# 翻译功能完整设计方案

## 概述

本文档涵盖 ProjectU 中所有翻译功能的设计方案，包括：
1. **作品标题与小说标题翻译** - 详情页标题的即时翻译
2. **作品简介与小说简介翻译** - 详情页简介的即时翻译
3. **小说阅读内容翻译** - 阅读页面的显示模式切换与分页翻译

## 一、作品标题与小说标题翻译方案

### 设计目标

在作品详情页和小说详情页提供标题翻译功能，与简介翻译统一操作，但采用差异化展示策略：
- **标题**：译文替换原文（保留原文小字提示）
- **简介**：原文和译文对照展示

### 适用场景

- ✅ 作品详情页标题
- ✅ 小说详情页标题
- ✅ 小说阅读页顶部标题栏
- ❌ 列表场景（不翻译）
- ❌ 文件命名（不翻译）
- ❌ 导出内容（不翻译）

### 核心设计原则

1. **统一操作**：一个翻译按钮同时控制标题和简介的翻译
2. **差异展示**：
   - 标题短小，译文替换原文更清晰
   - 简介较长，对照展示便于比较质量
3. **即时翻译**：用户点击按钮时才翻译，不自动翻译
4. **临时缓存**：翻译结果保存在内存中，退出页面后清除

### ViewModel 实现

```kotlin
/**
 * 统一翻译：同时翻译标题和简介
 */
fun translateContent() {
    val artwork = _state.value.artwork ?: return
    
    if (!settingsCache.isTranslationEnabled()) return
    
    viewModelScope.launch {
        _state.update { it.copy(isTranslating = true) }
        
        try {
            // 并发翻译标题和简介，提高效率
            val titleDeferred = async {
                if (artwork.title.isNotBlank()) {
                    translateTextUseCase(
                        text = artwork.title,
                        targetLanguage = settingsCache.getTranslationTargetLanguage(),
                        engine = settingsCache.getTranslationEngine()
                    )
                } else null
            }
            
            val descDeferred = async {
                if (artwork.description.isNotBlank()) {
                    translateTextUseCase(
                        text = artwork.description,
                        targetLanguage = settingsCache.getTranslationTargetLanguage(),
                        engine = settingsCache.getTranslationEngine()
                    )
                } else null
            }
            
            val titleResult = titleDeferred.await()
            val descResult = descDeferred.await()
            
            _state.update {
                it.copy(
                    translatedTitle = titleResult?.getOrNull()?.translatedText,
                    translatedDescription = descResult?.getOrNull()?.translatedText,
                    isTranslating = false
                )
            }
        } catch (e: Exception) {
            _state.update { it.copy(isTranslating = false) }
        }
    }
}

/**
 * 清除翻译：同时清除标题和简介的翻译
 */
fun clearTranslation() {
    _state.update {
        it.copy(
            translatedTitle = null,
            translatedDescription = null
        )
    }
}
```

```kotlin
        }
```

## 二、作品简介与小说简介的翻译方案（现有实现）

### 当前翻译机制

目前，作品详情页（`ArtworkInfoSection`）和小说详情页（`NovelInfoSection`）的简介翻译采用**即时翻译 + 手动切换**的方案：

#### 1. 翻译触发方式

- **手动触发**：用户点击"翻译"按钮触发翻译请求
- **条件显示**：翻译按钮仅在翻译引擎不为 `NONE` 时显示
- **单次翻译**：每次只翻译当前查看的作品/小说简介

#### 2. 状态管理

```kotlin
// ArtworkDetailState / NovelDetailState
data class DetailState(

    val isTranslating: Boolean = false,         // 是否正在翻译
    // ... 其他字段
)
```

#### 3. UI 交互逻辑

**默认状态（显示原文）**：
- 显示原始简介内容
- 翻译按钮可用，图标为 `Icons.Default.Translate`
- 按钮文案：「翻译」

**翻译中状态**：
- 显示原始简介
- 翻译按钮禁用，显示加载指示器
- 用户可以继续阅读原文

**已翻译状态（显示翻译）**：
- 显示翻译后的简介
- 按钮图标切换为 `Icons.Default.Close`
- 按钮文案：「清除翻译」或「显示原文」
- 点击按钮可切换回原文

#### 6. 特点总结

**优点**：
- ✅ 实现简单，逻辑清晰
- ✅ 用户可控，按需翻译
- ✅ 节省 API 调用，降低成本
- ✅ 状态管理简单，无需持久化
- ✅ 支持快速切换原文/翻译

**缺点**：
- ❌ 翻译不持久化，退出后丢失
- ❌ 每次打开需要重新翻译
- ❌ 无法批量翻译多个作品
- ❌ 翻译结果无法导出或分享

**适用场景**：
- 作品简介：文本较短（通常 < 1000 字），翻译快速
- 小说简介：单次查看，翻译结果临时性使用
- 偶发需求：用户不是每次都需要翻译

### 三种翻译方案的对比

| 特性 | 标题翻译 | 简介翻译 | 阅读翻译 |
|------|---------|---------|---------|
| **文本长度** | 极短（< 50 字） | 短文本（< 1K 字） | 长文本（> 10K 字） |
| **翻译粒度** | 单个标题 | 整段简介 | 分页翻译 |
| **触发方式** | 手动点击（与简介统一） | 手动点击 | 自动 + 手动 |
| **持久化** | 不保存 | 不保存 | 缓存到数据库 |
| **显示模式** | 译文替换原文 | 原文 + 译文对照 | 原文/翻译/对照 |
| **性能要求** | 实时翻译即可 | 实时翻译即可 | 需要缓存优化 |
| **使用频率** | 偶尔使用 | 偶尔使用 | 高频使用 |
| **翻译成本** | 极低（极短文本） | 低（单次短文本） | 高（多页长文本） |
| **UI位置** | 详情页顶部 | 详情页信息区 | 阅读页主体 |

### 设计考量

**标题翻译和简介翻译**采用简单方案的原因：

1. **文本短**：标题几十字，简介几百字，翻译耗时 < 2 秒
2. **频率低**：用户不会频繁翻译同一个详情页
3. **临时性**：翻译结果用完即弃，无需长期保存
4. **成本低**：单次翻译 API 成本可忽略
5. **统一操作**：标题和简介相关联，一起翻译更合理

**小说阅读翻译**则面临不同的挑战：

1. **文本长**：小说正文可达数万字，需要分页处理
2. **频率高**：用户可能反复阅读同一页面
3. **持久性**：需要保存翻译结果，避免重复翻译
4. **成本高**：全文翻译成本显著，必须优化

因此，小说阅读需要更复杂的**显示模式切换 + 分页缓存**方案。

## 三、小说阅读内容翻译方案

### 方案选择：方案四 - 显示模式切换

### 核心特性

- **三种显示模式**：原文模式、翻译模式、对照模式
- **智能翻译**：翻译模式自动翻译全文，无需手动点击
- **翻译缓存**：翻译结果持久化，切换模式无需重新翻译
- **灵活切换**：通过按钮或设置项快速切换显示模式
- **导出支持**：支持导出纯翻译版本的小说内容

- **进入翻译/对照模式时**：
  - 检查翻译缓存是否存在
  - 若无缓存，自动开始翻译当前页面
  - 显示翻译进度指示器
  
- **翻页时**：
  - 在翻译/对照模式下，自动翻译新页面（若无缓存）
  - 背景翻译，不阻塞用户操作

#### ViewModel 方法

```kotlin
class NovelDetailViewModel {
    // 切换显示模式
    fun switchDisplayMode(mode: NovelDisplayMode) {
        _state.update { it.copy(displayMode = mode) }
        
        // 若切换到翻译/对照模式，触发自动翻译
        if (mode != NovelDisplayMode.ORIGINAL) {
            translateCurrentPageIfNeeded()
        }
    }
    
    // 翻译当前页面（若需要）
    private fun translateCurrentPageIfNeeded() {
        val currentPage = state.value.currentPage
        if (!state.value.pageTranslations.containsKey(currentPage)) {
            translatePage(currentPage)
        }
    }
    
    // 翻译指定页面
    private fun translatePage(pageIndex: Int) {
        viewModelScope.launch {
            val page = state.value.parsedPages.getOrNull(pageIndex) ?: return@launch
            
            _state.update { 
                it.copy(translatingPages = it.translatingPages + pageIndex) 
            }
            
            try {
                val result = translateDescriptionUseCase(
                    text = page.content,
                    targetLanguage = settingsCache.getTranslationTargetLanguage(),
                    engine = settingsCache.getTranslationEngine()
                )
                
                result.onSuccess { translated ->
                    _state.update {
                        it.copy(
                            pageTranslations = it.pageTranslations + (pageIndex to translated),
                            translatingPages = it.translatingPages - pageIndex
                        )
                    }
                    // 保存翻译缓存到数据库
                    saveTranslationCache(pageIndex, translated)
                }
                
                result.onFailure { error ->
                    _state.update {
                        it.copy(translatingPages = it.translatingPages - pageIndex)
                    }
                    // 可选：显示错误提示
                }
            } catch (e: Exception) {
                _state.update {
                    it.copy(translatingPages = it.translatingPages - pageIndex)
                }
            }
        }
    }
    
    // 翻译全文（可选功能）
    fun translateAllPages() {
        viewModelScope.launch {
            _state.update { it.copy(isAutoTranslating = true) }
            
            val pages = state.value.parsedPages
            pages.forEachIndexed { index, page ->
                if (!state.value.pageTranslations.containsKey(index)) {
                    translatePage(index)
                    // 更新进度
                    val progress = (index + 1).toFloat() / pages.size
                    _state.update { it.copy(translationProgress = progress) }
                }
            }
            
            _state.update { 
                it.copy(
                    isAutoTranslating = false,
                    translationProgress = null
                ) 
            }
        }
    }
    
    // 清除翻译缓存
    fun clearTranslationCache() {
        _state.update {
            it.copy(
                pageTranslations = emptyMap(),
                displayMode = NovelDisplayMode.ORIGINAL
            )
        }
    }
}
```

## 注意事项

### 1. 翻译缓存策略

- **缓存粒度**：按页面缓存，而非整篇小说
- **缓存键**：`${novelId}_${pageIndex}_${targetLanguage}`

- **懒加载翻译**：只翻译当前页面，不预加载

## 双语对照展示优化方案

### 当前实现分析

**数据结构：**
- **原文**：存储在 `NovelPage` 中，包含 `elements: List<ContentElement>`（段落、章节标题、图片等结构化数据）
- **译文**：存储在 `pageTranslations: Map<Int, String>`，是整页的纯文本字符串
- **分块**：翻译时按句子分块（每块最多4500字符），但分块信息在翻译完成后不保留

**UI 展示结构（BilingualPageContent）：**
```
LazyColumn:
  ├─ 标签："原文"
  ├─ 原文内容（逐元素渲染，保留格式）
  │   ├─ 段落1
  │   ├─ 章节标题
  │   ├─ 段落2
  │   ├─ 图片
  │   └─ ...
  ├─ 分隔线
  ├─ 标签："译文"
  └─ 译文内容（整块纯文本）
```

**特点：**
- ✅ 原文保留结构化信息（章节、图片、Ruby注音等）
- ✅ 用户可以完整对照阅读
- ❌ 译文是一整块纯文本，失去了结构信息
- ❌ 对照时需要上下滚动，不够直观

### 方案A：基于翻译分块交替展示

**概念：**
按照 `splitTextIntoChunks()` 的分块逻辑，将译文与对应的原文块交替展示：
```
原文块1（4500字符）
↓
译文块1
↓
原文块2（4500字符）
↓
译文块2
...
```

**问题分析：**

1. **语义对应不准确**
   - 翻译分块是按 API 限制（4500字符）和句子边界划分的
   - 原文的 `ContentElement` 是按段落、章节、图片等语义结构划分的
   - 两者边界不对应，例如：
     ```
     原文结构：段落A（3000字）→ 章节标题 → 段落B（2000字）
     翻译分块：块1（4500字，包含段落A + 标题 + 段落B前半部分）
     ```
   - 会导致：译文块1结束在段落B中间，用户体验混乱

2. **结构信息丢失**
   - 译文是纯文本，无法知道哪部分对应章节标题、哪部分对应段落
   - 内嵌图片无法嵌入到译文对应位置

3. **增量显示问题**
   - 当前实现：每块翻译完成后，将所有已翻译块合并显示
   - 如果按块交替展示，需要实时更新 UI 结构，性能开销大

**结论：不推荐** - 语义边界不匹配导致用户体验差

---

### 方案B：基于语义元素交替展示

**概念：**
按照原文的 `ContentElement` 逐个翻译，然后交替展示：
```
原文段落1
↓
译文段落1
↓
原文章节标题
↓
译文章节标题
↓
原文段落2
↓
译文段落2
```

**优势：**
- ✅ **语义对应完美**：每个元素的翻译紧跟在原文之后
- ✅ **结构清晰**：章节、段落、图片都能正确对齐
- ✅ **用户体验最佳**：无需大范围滚动即可对照阅读

**需要的改动：**

1. **数据结构变更**
   ```kotlin
   // 当前
   pageTranslations: Map<Int, String>  // 页码 → 整页译文
   
   // 改为
   elementTranslations: Map<Int, Map<Int, String>>  
   // 页码 → (元素索引 → 该元素的译文)
   ```

2. **翻译逻辑变更**
   - 不再翻译整页纯文本 `page.content`
   - 而是逐个翻译 `page.elements` 中的文本元素（跳过图片、空行）
   - 保存每个元素的译文到独立的映射中

3. **UI 渲染变更**
   ```kotlin
   LazyColumn {
       page.elements.forEachIndexed { index, element ->
           // 原文元素
           item { ContentElementDisplay(element) }
           
           // 对应的译文（如果有）
           val translation = elementTranslations[pageNumber]?.get(index)
           if (translation != null) {
               item { TranslatedElementDisplay(translation) }
           }
       }
   }
   ```

4. **缓存结构变更**
   - 数据库表需要改为按元素缓存
   - 或者在缓存中存储 JSON 格式的元素翻译映射

**挑战：**

1. **翻译效率**
   - 单个段落可能只有几十字，API 请求次数大幅增加
   - 解决方案：合并多个小段落翻译，然后拆分结果

2. **翻译上下文**
   - 逐段落翻译会丢失上下文信息，影响翻译质量
   - 例如：代词「他」在整页上下文中才能确定指代

3. **元素边界识别**
   - 翻译 API 返回的译文如何准确拆分到各个元素？
   - Google Translate 返回整块文本，没有元素边界标记

**结论：理想方案但实现复杂** - 需要大量改动且存在技术挑战

---

### 方案C：混合方案（推荐）

**概念：**
整页翻译（保持上下文），但在 UI 展示时智能拆分译文到各个元素：

1. **翻译阶段**：保持当前逻辑，翻译整页 `page.content`
2. **存储阶段**：保存完整译文字符串（当前实现）
3. **展示阶段**：根据原文元素长度比例，估算译文切分点

**实现示例：**

```kotlin
/**
 * 按原文元素比例拆分译文
 */
fun splitTranslationByElements(
    elements: List<ContentElement>,
    translation: String
): Map<Int, String> {
    // 1. 计算各元素文本长度
    val elementLengths = elements.mapIndexed { index, element ->
        index to when (element) {
            is ContentElement.Text -> element.content.length
            is ContentElement.ChapterTitle -> element.title.length
            else -> 0  // 图片、空行不翻译
        }
    }
    
    val totalLength = elementLengths.sumOf { it.second }
    if (totalLength == 0) return emptyMap()
    
    // 2. 按比例切分译文
    var currentPos = 0
    return elementLengths.mapNotNull { (index, length) ->
        if (length == 0) return@mapNotNull null
        
        val proportion = length.toFloat() / totalLength
        val segmentLength = (translation.length * proportion).toInt()
        val endPos = minOf(currentPos + segmentLength, translation.length)
        
        val segment = translation.substring(currentPos, endPos)
        currentPos = endPos
        
        index to segment
    }.toMap()
}
```

**UI 渲染：**
```kotlin
@Composable
fun BilingualPageContentWithElements(
    page: NovelPage,
    translation: String?,
    ...
) {
    // 拆分译文到各个元素
    val elementTranslations = remember(page, translation) {
        if (translation != null) {
            splitTranslationByElements(page.elements, translation)
        } else emptyMap()
    }
    
    LazyColumn {
        page.elements.forEachIndexed { index, element ->
            // 显示原文元素
            item {
                ContentElementDisplay(element, ...)
            }
            
            // 显示对应的译文片段
            val translationSegment = elementTranslations[index]
            if (translationSegment != null) {
                item {
                    Text(
                        text = translationSegment,
                        color = MaterialTheme.colorScheme.tertiary,
                        modifier = Modifier.padding(start = 16.dp, bottom = 8.dp)
                    )
                }
            }
        }
    }
}
```

**优势：**
- ✅ **实现成本低**：只需改 UI 渲染逻辑，不动翻译和存储
- ✅ **用户体验好**：实现段落级对照阅读
- ✅ **翻译质量高**：保持整页上下文
- ✅ **可逐步优化**：先按比例切分，后续可根据句子边界精细调整

**缺点：**
- ⚠️ 切分点不精确（但用户一般不会逐字对比）
- ⚠️ 如果原译文长度差异大（如翻译成英文），比例可能失效

**优化方向：**
1. **基于句子边界调整**：按比例估算后，在附近寻找句号等标点微调
2. **多语言系数**：中译英约1.5倍，中译日约0.8倍，可根据语言对调整比例
3. **用户反馈**：提供「重新对齐」按钮，允许用户手动微调

**结论：推荐实施** - 平衡了实现成本和用户体验
