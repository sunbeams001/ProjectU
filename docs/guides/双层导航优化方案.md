# 双层导航优化方案

> 📅 创建日期: 2026-01-03  
> 🎯 目标: 优化项目中所有使用双层导航的页面，提升用户体验和视觉层次  
> 📋 状态: 待实施

---

## 📊 现状分析

### 问题概述

项目中有 **5 个页面**使用了**双层导航**结构，都存在以下共性问题：

#### ⚠️ 主要问题

1. **视觉层次不清晰**
   - 两层导航使用相同的 `FilterChip` 样式，难以区分主次
   - 颜色、大小、样式过于相似，缺乏层次感
   - 用户难以理解两层导航的逻辑关系

2. **空间占用较大**
   - 两层导航各占约 44dp 高度（`6dp padding × 2 + 32dp chip`）
   - 在手机竖屏上总共占用约 **88-90dp**
   - 对于有三层导航的页面（如 FollowLatestMoreScreen），占用更高

3. **操作复杂度高**
   - 用户需要理解两层/三层导航的关系
   - 切换逻辑不够直观
   - 缺乏视觉引导

4. **不符合 Material Design 规范**
   - Material 3 推荐主导航使用 `Tab` 组件
   - FilterChip 更适合作为筛选器而非主导航

### 1. 发现页面 (DiscoveryTab)

**文件位置**: `composeApp/src/commonMain/kotlin/com/projectu/ui/screens/discovery/DiscoveryContent.kt`

**导航结构**:
```
┌─────────────────────────────────────────────────┐
│ 第1层: 用户 | 插画·漫画 | 小说                │  ← SimpleNavigationBar (FilterChip)
├─────────────────────────────────────────────────┤
│ 第2层: ⚪ALL | ⚪SAFE | ⚪R18                  │  ← SimpleNavigationBar (FilterChip)
└─────────────────────────────────────────────────┘
```

**功能说明**:
- 第1层：内容类型选择（支持 HorizontalPager 滑动）
- 第2层：内容筛选模式（插画和小说有 ALL/SAFE/R18，用户无）

**问题**:
- 两层都用 FilterChip，视觉层次不清晰
- 第2层对"用户"类型不适用，出现空白或隐藏

**推荐方案**: Tab + FilterChip

### 2. 动态页面 (FollowLatestTab)

**导航结构**:
```
┌─────────────────────────────────────────────────┐

│ 第2层: ⚪公开 | ⚪私密                         │  ← SimpleNavigationBar (FilterChip)
└─────────────────────────────────────────────────┘
```

**功能说明**:
- 第1层：内容类型选择（插画/小说）+ 尾部"更多"按钮
- 第2层：关注模式筛选（公开关注/私密关注）

**特点**:
- 右侧有尾部按钮（"更多"）
- 只有 2 个主分类，非常适合 SegmentedButton

**推荐方案**: SegmentedButton + FilterChip（或 Tab + FilterChip）

### 3. 排行榜页面 (RankingTab)

**文件位置**: `composeApp/src/commonMain/kotlin/com/projectu/ui/screens/ranking/RankingScreen.kt`

**导航结构**:
```
┌─────────────────────────────────────────────────┐
│ 第1层: 综合 | 插画 | 动图 | 漫画 | 小说 [日期]│  ← NavigationBar (FilterChip + 日期选择器)
├─────────────────────────────────────────────────┤
│ 第2层: ⚪每日 | ⚪每周 | ⚪每月 | ...          │  ← SimpleNavigationBar (FilterChip，可滚动)
└─────────────────────────────────────────────────┘
```

**功能说明**:
- 第1层：排行榜内容类型 + 日期选择器（右侧尾部）
- 第2层：排行榜时间范围（每日/每周/每月/男性向/女性向等，根据第1层动态变化）
  - **综合 (ALL)**: 16个模式（所有模式 - 3个小说专属）
  - **插画 (ILLUST)**: 7个模式
  - **动图 (UGOIRA)**: 4个模式
  - **漫画 (MANGA)**: 7个模式
  - **小说 (NOVEL)**: 14个模式（包含3个专属：本周原创/本周AI/本周R18-AI）

**特点**:
- 第1层有 5 个分类 + 日期选择器
- 第2层选项数量**各不相同**（最少4个，最多16个），需要横向滚动
- 第1层使用了 `NavigationBar`（支持尾部内容）
- **总计**: 16+7+4+7+14 = **48个页面**

**推荐方案**: 
- **方案A**: Tab + FilterChip（将日期选择器移到 Tab 右侧）
- **方案B**: Dropdown + FilterChip（第1层改为下拉菜单，节省空间）

### 4. FollowLatestMoreScreen（动态更多页面）

**文件位置**: `composeApp/src/commonMain/kotlin/com/projectu/ui/screens/followlatest/more/FollowLatestMoreScreen.kt`

**导航结构**:
```
┌─────────────────────────────────────────────────┐
│ 第1层: 追更列表 | 好P友                        │  ← SimpleNavigationBar (FilterChip)
├─────────────────────────────────────────────────┤
│ 第2层: 漫画 | 小说                             │  ← SimpleNavigationBar (FilterChip，仅"追更列表"显示)
└─────────────────────────────────────────────────┘
```

**功能说明**:
- 第1层：主功能选择（追更列表 / 好P友）
- 第2层：内容类型（漫画 / 小说），仅在"追更列表"下显示
- 无 TopAppBar（独立页面，可优化为全屏导航）

**当前滑动行为**:
- 第1层 HorizontalPager（追更列表/好P友）
- 第2层在"追更列表"内部嵌套 HorizontalPager（漫画/小说）

- 双层导航占用空间较大（约 88dp）

- 建议移除 TopAppBar，使用系统返回按钮或将标题集成到第1层导航

**推荐方案**: 
- **方案A**: Tab + SegmentedButton（第1层用 Tab，第2层用 SegmentedButton，更紧凑）
- **方案B**: 扁平化重构（"追更-漫画"、"追更-小说"、"好P友"作为同级 Tab，最简洁）

**导航结构**:
```
┌─────────────────────────────────────────────────┐
│ 第1层: 已关注 | 好P友 | [粉丝]                │  ← SimpleNavigationBar (FilterChip)
├─────────────────────────────────────────────────┤
│ 第2层: ⚪公开 | ⚪私密                         │  ← SimpleNavigationBar (FilterChip，仅"已关注"显示)
└─────────────────────────────────────────────────┘
```

**功能说明**:
- 第1层：关系类型（已关注 / 好P友 / 粉丝）
  - 查看自己：显示 3 个选项
  - 查看他人：只显示 2 个选项（无"粉丝"）
- 第2层：关注可见性（公开 / 私密），仅在"已关注"时显示
- 无 TopAppBar 标题栏（建议移除或集成到第1层导航，标题可用系统标题或嵌入导航）

**当前滑动行为**:
- 单一 HorizontalPager，管理所有页面（已关注-公开 / 已关注-私密 / 好P友 / 粉丝）
- 滑动时直接在这4个页面之间切换，第1层/第2层导航同步更新
- 逻辑最复杂：需要处理导航栏点击与 Pager 的双向同步

**特点**:
- 动态显示：第2层仅在第1层选中"已关注"时出现
- 条件性导航：查看自己和查看他人的选项数量不同
- 复杂的状态管理：需要处理主次导航的联动

**问题**:
- 第2层出现/消失会导致界面跳动
- 两层 FilterChip 难以区分主次
- 用户需要理解"已关注"才有"公开/私密"的逻辑
- 滑动行为与嵌套逻辑不一致（实际是扁平的4页，但导航显示为两层）

**推荐方案**: 
- **方案A**: Tab + FilterChip（主次分明，FilterChip 动态显示更自然）
- **方案B**: 扁平化（"已关注-公开"、"已关注-私密"、"好P友"、"粉丝"作为同级 Tab，最清晰）

## � 滑动切换行为分析

### 当前各页面的滑动逻辑

各页面的 HorizontalPager 配置和滑动行为各不相同：

| 页面 | Pager 位置 | 滑动行为 | 切换对象 | 嵌套关系 |
|------|-----------|---------|---------|----------|
| **发现页面** | 第1层 | 左右滑动切换内容类型 | 用户/插画/小说（3页） | 第2层固定，不随滑动切换 |
| **动态页面** | 第1层 | 左右滑动切换内容类型 | 插画/小说（2页） | 第2层在每个内容类型内独立（公开/私密） |
| **排行榜页面** | 第2层 | 左右滑动切换模式 | 每日/每周/每月等（7页） | 第1层固定，滑动只影响第2层 |
| **FollowLatestMore** | 嵌套两层 | 第1层切换追更/好P友<br>第2层在追更内切换漫画/小说 | 第1层2页，第2层2页 | 嵌套Pager，第2层独立 |
| **UserRelations** | 单一扁平 | 直接切换所有页面 | 4页扁平结构 | 虽有两层导航UI，但Pager是扁平的 |

### 问题分析

**不一致性问题**:
1. **发现页面、动态页面**：滑动切换第1层（内容类型），每个类型内的第2层（筛选模式）不随滑动变化
2. **排行榜页面**：滑动切换第2层（时间模式），第1层（内容类型）保持固定
3. **FollowLatestMore**：嵌套 Pager，第1层切换主功能，第2层独立切换（仅在追更列表内）
4. **UserRelations**：虽然有两层导航UI，但实际是单一扁平Pager（4个页面），滑动直接跨越导航层级

**用户体验问题**:
- 不同页面的滑动行为不一致，增加学习成本
- 用户无法预测滑动会切换哪一层
- 有些页面滑动切换主分类，有些切换次分类

### 嵌套Pager方案的问题 ⚠️

之前考虑的**嵌套 Pager 模式**（先切换第2层，到底后切换第1层）存在严重问题：

**技术难点**：
1. **边界触发困难**：需要精确检测内层Pager滑到边界并继续拖动，才能触发外层切换
2. **滑动冲突**：嵌套滑动容易出现手势冲突，用户难以控制滑动方向
3. **状态同步复杂**：需要维护多个Pager状态，以及导航栏与Pager的双向同步
4. **性能开销**：每个外层页面都需要独立的内层Pager状态，内存占用增加

**用户体验差**：
- 用户需要精确控制滑动力度才能切换到外层，手感不好
- 边界触发阈值难以调校（太敏感会误触发，太钝会无响应）
- 快速滑动时行为难以预测
- 不同场景下的边界行为不一致

### 统一滑动行为方案 ⭐（推荐）

**新方案**：**一层 Pager + 动态页码映射**

**核心思想**：
- 只使用一个 `HorizontalPager`，包含所有实际页面
- 两层导航UI通过**页码映射算法**计算当前应该高亮哪个导航项
- 点击导航时，计算目标页码并跳转到对应页面
- 滑动时，Pager自动切换页面，导航栏根据当前页码更新高亮状态

**优势**：
- ✅ 滑动体验流畅，无嵌套冲突
- ✅ 实现简单，只需维护一个Pager状态
- ✅ 导航逻辑清晰，易于理解和维护
- ✅ 性能更好，内存占用更少
- ✅ 手感自然，用户左右滑动即可顺序浏览所有页面

**实现示例（以发现页面为例）**：

```kotlin
@OptIn(ExperimentalFoundationApi::class)
@Composable
fun DiscoveryContent() {
    // 定义页面结构
    val contentTypes = listOf(
        DiscoveryContentType.USERS,      // 索引 0
        DiscoveryContentType.ILLUSTS,    // 索引 1-3（ALL/SAFE/R18）
        DiscoveryContentType.NOVELS      // 索引 4-6（ALL/SAFE/R18）
    )
    val modes = listOf(
        DiscoveryMode.ALL,
        DiscoveryMode.SAFE,
        DiscoveryMode.R18
    )
    
    // 页面映射：
    // 用户: 0
    // 插画-ALL: 1, 插画-SAFE: 2, 插画-R18: 3
    // 小说-ALL: 4, 小说-SAFE: 5, 小说-R18: 6
    val totalPages = 1 + 3 + 3 // 总共7个页面
    
    val pagerState = rememberPagerState(
        initialPage = 0,
        pageCount = { totalPages }
    )
    val coroutineScope = rememberCoroutineScope()
    
    // 根据当前页码反向计算第1层和第2层的索引
    val (primaryIndex, secondaryIndex) = remember {
        derivedStateOf {
            when (pagerState.currentPage) {
                0 -> 0 to 0      // 用户（第2层导航不显示）
                in 1..3 -> 1 to (pagerState.currentPage - 1)  // 插画
                in 4..6 -> 2 to (pagerState.currentPage - 4)  // 小说
                else -> 0 to 0
            }
        }
    }.value
    
    val showSecondaryNav = primaryIndex > 0  // 用户类型不显示第2层导航
    
    Column {
        // 第1层导航
        SimpleNavigationBar(
            items = contentTypes,
            selectedIndex = primaryIndex,
            onItemClick = { index ->
                val targetPage = when (index) {
                    0 -> 0          // 用户
                    1 -> 1          // 插画-ALL（默认第一页）
                    2 -> 4          // 小说-ALL（默认第一页）
                    else -> 0
                }
                coroutineScope.launch {
                    pagerState.animateScrollToPage(targetPage)
                }
            }
        )
        
        // 第2层导航（条件显示）
        if (showSecondaryNav) {
            SimpleNavigationBar(
                items = modes,
                selectedIndex = secondaryIndex,
                onItemClick = { index ->
                    // 计算目标页码：基础偏移 + 模式索引
                    val baseOffset = if (primaryIndex == 1) 1 else 4
                    val targetPage = baseOffset + index
                    coroutineScope.launch {
                        pagerState.animateScrollToPage(targetPage)
                    }
                }
            )
        }
        
        // 单一 HorizontalPager
        HorizontalPager(
            state = pagerState,
            modifier = Modifier.fillMaxSize()
        ) { page ->
            when (page) {
                0 -> UsersPage()              // 用户
                1 -> IllustsPage(mode = ALL)  // 插画-ALL
                2 -> IllustsPage(mode = SAFE) // 插画-SAFE
                3 -> IllustsPage(mode = R18)  // 插画-R18
                4 -> NovelsPage(mode = ALL)   // 小说-ALL
                5 -> NovelsPage(mode = SAFE)  // 小说-SAFE
                6 -> NovelsPage(mode = R18)   // 小说-R18
            }
        }
    }
}
```

### 各页面映射方案

| 页面 | 总页数 | 页码映射规则 | 示例 |
|------|-------|------------|------|
| **发现页面** | 7页 | 用户(0)、插画×3(1-3)、小说×3(4-6) | 点击"插画-SAFE"→跳转到页码2 |
| **动态页面** | 4页 | 插画×2(0-1)、小说×2(2-3) | 点击"小说-私密"→跳转到页码3 |
| **排行榜页面** | 48页 | 综合×16(0-15)、插画×7(16-22)、动图×4(23-26)、漫画×7(27-33)、小说×14(34-47) | 点击"插画-每周"→计算页码 |
| **FollowLatestMore** | 3页 | 追更-漫画(0)、追更-小说(1)、好P友(2) | 点击"追更-小说"→跳转到页码1 |
| **UserRelations** | 4页 | 关注-公开(0)、关注-私密(1)、好P友(2)、粉丝(3) | 已采用此方案✅ |

**实现要点**：
1. **页码映射算法**：定义清晰的页码计算规则，支持正向和反向映射
2. **状态计算**：使用 `derivedStateOf` 根据当前页码计算导航状态，避免不必要的重组
3. **条件导航**：第2层导航根据第1层的选择动态显示/隐藏
4. **重复点击处理**：点击已选中的导航项时，触发"滚动到顶部或刷新"逻辑

## �💡 统一优化方案

### 推荐方案：Tab + FilterChip ⭐

**设计原则**:
1. **第1层使用 Material 3 TabRow**
   - 表示主要分类或功能
   - 有下划线指示器，视觉明确
   - 固定高度 48dp

2. **第2层使用 FilterChip**
   - 表示筛选条件或次级分类
   - 可横向滚动
   - 高度 32dp + padding 12dp = 约 44dp

3. **总高度**: 48dp + 44dp = **92dp**（相比当前节省空间不多，但视觉层次更清晰）

---

### 方案对比

| 方案 | 第1层 | 第2层 | 优势 | 劣势 | 适用场景 |
|------|-------|-------|------|------|----------|
| **方案1** | TabRow | FilterChip | ✅ 视觉层次清晰<br>✅ 符合规范<br>✅ 用户认知成本低 | - | **所有页面（推荐）** |
| **方案2** | SegmentedButton | FilterChip | ✅ 更紧凑（80dp）<br>✅ 适合2-3个分类 | ❌ 分类多时拥挤 | 动态页面（2个分类） |
| **方案3** | Dropdown | FilterChip | ✅ 最节省空间（60dp） | ❌ 需额外点击<br>❌ 不支持滑动 | 排行榜（5个分类） |
| **方案4** | Tab | SegmentedButton | ✅ 第2层更紧凑 | ❌ 第2层不支持滚动 | FollowLatestMore（2个子分类） |
| **方案5** | Tab | Dropdown | ✅ 避免界面跳动 | ❌ 第2层交互繁琐 | UserRelations（动态显示） |

## 🎨 设计规范

### TabRow 样式规范

```kotlin
TabRow(
    selectedTabIndex = selectedIndex,
    containerColor = MaterialTheme.colorScheme.surface,  // 使用 surface 而非 surfaceContainer
    contentColor = MaterialTheme.colorScheme.primary,
    indicator = { tabPositions ->
        TabRowDefaults.SecondaryIndicator(
            Modifier.tabIndicatorOffset(tabPositions[selectedIndex]),
            color = MaterialTheme.colorScheme.primary
        )
    }
) {
    Tab(
        selected = selectedIndex == index,
        onClick = { /* 切换 */ },
        text = { Text("标签文本") }
    )
}
```

**样式特点**:
- 高度：48dp（Material 3 标准）
- 指示器：2dp 高度的下划线
- 文字：使用 `titleSmall` 或 `labelLarge`
- 颜色：选中时用 primary，未选中时用 onSurfaceVariant

### FilterChip 样式规范（保持不变）

```kotlin
FilterChip(
    selected = isSelected,
    onClick = { /* 切换 */ },
    label = { Text("筛选项") }
)
```

**样式特点**:
- 高度：32dp
- 背景：选中时用 secondaryContainer，未选中时用透明
- 外边距：horizontal=16.dp, vertical=6.dp

### 3. 实施一层Pager + 页码映射

**核心步骤**：

1. **定义页面结构和映射规则**
   ```kotlin
   // 示例：发现页面
   data class PageMapping(
       val totalPages: Int,
       val primaryIndex: Int,     // 第1层索引
       val secondaryIndex: Int,   // 第2层索引
       val showSecondary: Boolean // 是否显示第2层导航
   )
   
   // 正向映射：(第1层索引, 第2层索引) → 页码
   fun calculatePageIndex(primary: Int, secondary: Int): Int {
       return when (primary) {
           0 -> 0                          // 用户
           1 -> 1 + secondary              // 插画（1-3）
           2 -> 4 + secondary              // 小说（4-6）
           else -> 0
       }
   }
   
   // 反向映射：页码 → (第1层索引, 第2层索引)
   fun parsePageIndex(page: Int): PageMapping {
       return when (page) {
           0 -> PageMapping(7, 0, 0, false)
           in 1..3 -> PageMapping(7, 1, page - 1, true)
           in 4..6 -> PageMapping(7, 2, page - 4, true)
           else -> PageMapping(7, 0, 0, false)
       }
   }
   ```

2. **创建单一Pager**
   ```kotlin
   val pagerState = rememberPagerState(
       initialPage = initialPageCalculated,
       pageCount = { totalPages }
   )
   ```

3. **使用derivedStateOf计算导航状态**
   ```kotlin
   val mapping by remember {
       derivedStateOf { parsePageIndex(pagerState.currentPage) }
   }
   ```

4. **导航栏点击计算目标页码**
   ```kotlin
   onItemClick = { index ->
       val targetPage = calculatePageIndex(index, currentSecondaryIndex)
       coroutineScope.launch {
           pagerState.animateScrollToPage(targetPage)
       }
   }
   ```

## 💬 备注

### 关于移除 TopAppBar 的说明

**FollowLatestMoreScreen** 和 **UserRelationsScreen** 都是独立的全屏页面，建议：

1. **移除 TopAppBar**
   - 使用系统返回按钮代替导航返回图标
   - 或者将标题文本集成到第1层导航栏
   - 节省约 56dp 的垂直空间

2. **替代方案**（如需保留标题）
   - 使用 Material 3 的 LargeTopAppBar，标题可收起
   - 或使用 Surface 包裹第1层导航，添加标题文本

### 关于一层Pager方案的优势

采用一层Pager + 动态页码映射方案相比嵌套Pager有明显优势：

1. **滑动体验**：无嵌套冲突，左右滑动顺序浏览所有页面，直观自然
2. **实现复杂度**：只需维护一个Pager状态，逻辑简单清晰
3. **性能**：内存占用更少，渲染开销更小
4. **可维护性**：页码映射逻辑集中，易于理解和修改

**代价**：
- 需要实现页码映射算法（正向和反向）
- 不同页面的映射规则不同，需要针对性设计

### 关于UserRelations页面的现状

UserRelationsScreen 实际上已经采用了一层Pager方案（扁平的4个页面），只需要进行视觉优化：
- 第1层改用 TabRow
- 第2层保持 FilterChip
- 保持现有的Pager结构和页面切换逻辑

### 关于排行榜页面的特殊处理

排行榜页面第1层有 **5 个分类 + 日期选择器**，如果使用 TabRow，可能比较拥挤。建议：

1. **方案A（推荐）**: 保持 TabRow，将日期选择器移到 TabRow 的 `actions` 参数
   ```kotlin
   TopAppBar(
       title = { TabRow(...) },
       actions = { DatePickerButton() }
   )
   ```

2. **方案B**: 使用 ScrollableTabRow（支持横向滚动）
   ```kotlin
   ScrollableTabRow(
       selectedTabIndex = selectedIndex,
       edgePadding = 16.dp
   )
   ```

3. **方案C**: 第1层改为下拉菜单（节省空间，但失去滑动手势）

### 关于 FollowLatestMoreScreen 的重构建议

考虑扁平化重构，将三层导航简化为两层：

```
旧结构（三层）:
追更列表 - 漫画
追更列表 - 小说
好P友

新结构（两层/扁平化）:
追更 - 漫画
追更 - 小说
好P友
```

这样可以：
- 减少一层导航（从 130dp 降到 92dp）
- 简化用户理解成本
- 保持功能完整性
