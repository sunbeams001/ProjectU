## 一、项目概述

ProjectU 是一个基于 Kotlin Multiplatform 的跨平台 Pixiv 客户端，支持 Android 和 Desktop 平台。项目采用 Clean Architecture + MVI 架构模式，使用最新的 Compose Multiplatform 技术栈。

### 核心特性

- 🎨 **跨平台支持**: Android (API 24+) 和 Desktop (Windows/Mac/Linux)
- 🌍 **完整多语言**: 简体中文、繁体中文、英文、日文、韩文
- 🎭 **Material Design 3**: 深色/浅色主题，Pixiv 风格配色
- 🏗️ **Clean Architecture**: Domain + Data + Presentation 分层
- 🔄 **MVI 架构**: 单向数据流，可预测的状态管理
- 🌐 **Pixiv Web API**: 完整集成官方 Web API
- 🎬 **Ugoira 支持**: Pixiv 动图下载和播放
- 📱 **响应式设计**: 自适应手机/平板/桌面布局

## 三、架构设计

### 3.1 Clean Architecture 分层

项目严格遵循 Clean Architecture 原则，实现关注点分离和依赖倒置：

```
┌─────────────────────────────────────────────────────────────┐
│                   Presentation Layer                        │
│                  (composeApp 模块)                           │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  UI (Jetpack Compose)                                 │  │
│  │  • Screens - 页面实现（HomeScreen, SettingsScreen）    │  │
│  │  • Components - 可复用 UI 组件（UgoiraPlayer）        │  │
│  │  • ViewModels - 状态管理（SettingsViewModel）         │  │
│  │  • Theme - Material 3 主题配置                        │  │
│  │  • Localization - 多语言支持（LocaleManager）         │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                           ↓ 依赖
┌─────────────────────────────────────────────────────────────┐
│                     Domain Layer                            │
│               (shared/domain/)                              │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  Business Logic (纯 Kotlin，无外部依赖)               │  │
│  │  • Models - 领域模型（Artwork）                       │  │
│  │  • Repository Interfaces - 数据访问接口               │  │
│  │  • UseCases - 业务用例（GetUgoiraUseCase）           │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                           ↓ 实现
┌─────────────────────────────────────────────────────────────┐
│                      Data Layer                             │
│                 (shared/data/)                              │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  Data Sources & Repository Implementations            │  │
│  │  • Repository Impl - 实现 Domain 接口                 │  │
│  │  • Remote (Ktor) - Pixiv Web API 客户端              │  │
│  │  • Local (Room) - SQLite 数据库持久化                │  │
│  │  • Cache (Okio) - 文件缓存和 ZIP 处理                │  │
│  │  • DataStore - 键值对配置存储                        │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

**依赖规则**:
- ✅ Presentation 层可依赖 Domain 层（通过接口）
- ✅ Data 层实现 Domain 层定义的接口
- ❌ Domain 层不依赖任何外部框架
- ❌ Data 层不能直接被 Presentation 调用

### 3.2 MVI (Model-View-Intent) 架构

每个 Screen 都遵循 MVI 单向数据流模式：

```
┌──────────────────────────────────────────────────────────┐
│                         View                              │
│          (Composable Functions)                          │
│  • 渲染 State                                            │
│  • 发出 Intent                                           │
└──────────────────────────────────────────────────────────┘
            │                                    ↑
            │ User Intent                        │ State Update
            ↓                                    │
┌──────────────────────────────────────────────────────────┐
│                      ViewModel                            │
│  • 接收 Intent                                           │
│  • 调用 UseCase                                          │
│  • 更新 State (StateFlow)                                │
└──────────────────────────────────────────────────────────┘
            │                                    ↑
            │ UseCase Call                       │ Result
            ↓                                    │
┌──────────────────────────────────────────────────────────┐
│                      UseCase                              │
│  • 业务逻辑处理                                          │
│  • 调用 Repository                                       │
└──────────────────────────────────────────────────────────┘
            │                                    ↑
            │ Data Request                       │ Data Response
            ↓                                    │
┌──────────────────────────────────────────────────────────┐
│                     Repository                            │
│  • 协调多个数据源                                        │
│  • 缓存策略                                              │
│  • 数据映射 (DTO → Domain Model)                        │
└──────────────────────────────────────────────────────────┘
            │                                    │
      ┌─────┴───────┬──────────────────┬────────┴─────┐
      ↓             ↓                  ↓              ↓
┌─────────┐  ┌──────────┐    ┌─────────────┐  ┌──────────┐
│ Remote  │  │  Local   │    │   Cache     │  │DataStore │
│  API    │  │   DB     │    │   (File)    │  │  (KV)    │
│ (Ktor)  │  │ (Room)   │    │  (Okio)     │  │          │
└─────────┘  └──────────┘    └─────────────┘  └──────────┘
```

**实际示例 (SettingsScreen)**:

```kotlin
// State - 屏幕状态
data class SettingsScreenState(
    val appLanguage: AppLanguage,
    val pixivLanguage: PixivLanguage,
    val themeMode: ThemeMode,
    val isLoading: Boolean = false
)

// Intent - 用户操作
sealed interface SettingsIntent {
    data class ChangeAppLanguage(val language: AppLanguage) : SettingsIntent
    data class ChangePixivLanguage(val language: PixivLanguage) : SettingsIntent
    data class ChangeTheme(val mode: ThemeMode) : SettingsIntent
}

// ViewModel - 状态管理
class SettingsViewModel(
    private val settingsRepository: SettingsRepository
) : ViewModel() {
    private val _state = MutableStateFlow(SettingsScreenState(...))
    val state: StateFlow<SettingsScreenState> = _state.asStateFlow()
    
    fun handleIntent(intent: SettingsIntent) {
        when (intent) {
            is SettingsIntent.ChangeAppLanguage -> {
                viewModelScope.launch {
                    settingsRepository.updateAppLanguage(intent.language)
                }
            }
            // ... 其他 Intent 处理
        }
    }
}
```

### 3.3 依赖注入 (Koin)

使用 Koin 实现跨平台依赖注入，支持平台特定实现：

**通用模块** (`composeApp/di/AppModule.kt`):
```kotlin
val commonModule = module {
    single { LocaleManager(get()) }
}
```

**平台特定模块** (`PlatformModule.android.kt` / `PlatformModule.desktop.kt`):
```kotlin
// Android
actual val networkModule = module {
    single { NetworkClient.create(CIO.create()) }
}

actual val databaseModule = module {
    single { getRoomDatabase(getDatabaseBuilder()) }
    single<SettingsDao> { get<AppDatabase>().settingsDao() }
}

// Desktop 也有对应实现，使用不同的数据库路径
```

**模块组织结构**:
```
initKoin()
  ├── commonModule        (跨平台共享)
  ├── networkModule       (平台特定: CIO Engine)
  ├── databaseModule      (平台特定: Room DB 路径)
  ├── repositoryModule    (共享: Repository 实现)
  ├── useCaseModule       (共享: UseCase)
  └── viewModelModule     (平台特定: Android 用 viewModel {})
```

## 四、模块依赖关系

### 4.1 Gradle 模块依赖

```
┌─────────────────┐
│   composeApp    │  (Android App / Desktop App)
│                 │
│  • UI 层        │
│  • ViewModels   │
│  • Navigation   │
│  • Themes       │
└────────┬────────┘
         │ implementation(projects.shared)
         ↓
┌─────────────────┐
│     shared      │  (Kotlin Multiplatform Library)
│                 │
│  • Domain 层    │
│  • Data 层      │
│  • Repositories │
│  • UseCases     │
└─────────────────┘
```

**原则**:
- composeApp 依赖 shared（单向依赖）
- shared 是独立的 KMP 库，可复用到其他项目
- 不存在循环依赖

### 4.2 架构层级依赖

```
Presentation Layer (composeApp)
         │
         │ 依赖 Repository 接口
         ↓
Domain Layer (shared/domain)        ← 核心业务逻辑，无外部依赖
         ↑
         │ 实现接口
         │
Data Layer (shared/data)
         │
         ├─→ Remote (Ktor)
         ├─→ Local (Room)
         ├─→ Cache (Okio)
         └─→ DataStore
```

**依赖倒置原则 (DIP)**:
- Domain 层定义 `Repository` 接口
- Data 层实现 `RepositoryImpl`
- Presentation 层通过 Koin 注入接口，不直接依赖实现类

### 5.3 Ugoira 动图处理

Pixiv 的 Ugoira (うごイラ) 是一种特殊的动图格式，由多张静态图片按时序播放。

#### 处理流程

```
1. 获取元数据
   ↓
   IllustApi.getUgoiraMeta(illustId)
   返回: { zipUrl, frames: [{ delay: 100 }, ...] }

2. 下载 ZIP 文件
   ↓
   UgoiraCache.downloadAndExtract(zipUrl, illustId)
   保存到: Android - cache/ugoira/
          Desktop - ~/.projectu/cache/ugoira/

3. 解压图片帧
   ↓
   [Platform-specific]
   Android: java.util.zip.ZipInputStream
   Desktop: java.util.zip.ZipFile
   
4. 播放动画
   ↓
   UgoiraPlayer Composable
   使用 LaunchedEffect + delay 循环播放
```

#### 关键实现

**缓存管理** (`UgoiraCache.kt`):
```kotlin
class UgoiraCache(private val cacheDir: File) {
    suspend fun downloadAndExtract(
        zipUrl: String, 
        illustId: String
    ): List<File> {
        val zipFile = downloadZip(zipUrl, illustId)
        return extractZipPlatform(zipFile, illustId)  // expect 函数
    }
    
    fun getFrames(illustId: String): List<File> {
        return File(cacheDir, illustId).listFiles()
            ?.sortedBy { it.name } 
            ?: emptyList()
    }
}
```

**播放器组件** (`UgoiraPlayer.kt`):
```kotlin
@Composable
fun UgoiraPlayer(
    frames: List<File>,          // 图片帧文件
    delays: List<Int>,           // 每帧延迟（毫秒）
    modifier: Modifier = Modifier
) {
    var currentFrame by remember { mutableStateOf(0) }
    
    LaunchedEffect(frames, delays) {
        while (true) {
            delay(delays[currentFrame].toLong())
            currentFrame = (currentFrame + 1) % frames.size
        }
    }
    
    AsyncImage(
        model = frames[currentFrame],
        contentDescription = null,
        modifier = modifier
    )
}
```

class IllustApi(private val client: PixivApiClient) {
    suspend fun getComments(illustId: String): List<CommentDto> {
        return client.get("/ajax/illusts/comments/roots") {
            parameter("illust_id", illustId)
        }
    }

data class Comment(
    val id: String,
    val content: String,
    val user: User

// 5. Repository Interface
interface CommentRepository {
    suspend fun getComments(illustId: String): Result<List<Comment>>

// 6. Repository Implementation
class CommentRepositoryImpl(
    private val pixivApi: PixivApi
) : CommentRepository {
    override suspend fun getComments(illustId: String): Result<List<Comment>> {
        return try {
            val comments = pixivApi.illustApi.getComments(illustId)
            Result.success(comments.map { it.toDomain() })
        } catch (e: Exception) {
            Result.failure(e)
        }
    }
}

### 8.5 注意事项

#### 平台差异处理
使用 `expect`/`actual` 关键字：

```kotlin
// commonMain
expect fun calculateWindowSizeClass(): WindowSizeClass

// androidMain
actual fun calculateWindowSizeClass(): WindowSizeClass {
    // Android 实现
}

// desktopMain
actual fun calculateWindowSizeClass(): WindowSizeClass {
    // Desktop 实现
}
```

#### 协程作用域
- UI 层: `viewModelScope.launch { }`
- Repository 层: `withContext(Dispatchers.IO) { }`
- 数据库操作: Room 自动处理，无需手动切换

#### 错误处理
统一使用 `Result<T>`:

```kotlin
suspend fun fetchData(): Result<Data> {
    return try {
        val data = api.getData()
        Result.success(data)
    } catch (e: Exception) {
        Result.failure(e)
    }
}

// 使用时
result.onSuccess { data ->
    // 处理成功
}.onFailure { error ->
    // 处理错误
}
```

#### 资源释放
- 图片加载使用 Coil，自动管理内存
- 文件流需要使用 `use { }` 自动关闭
- Room 数据库连接由框架管理
