# 配置管理统一框架设计文档

## 架构概览

```
┌─────────────────────────────────────────────────────────────┐
│                     UI Layer (ViewModel)                     │
│  SettingsViewModel.updateR18Threshold() 等                  │
└─────────────────┬───────────────────────────────────────────┘
                  ↓ (写入)
┌─────────────────────────────────────────────────────────────┐
│                  Repository Layer                            │
│  SettingsRepository.updateR18SanityLevelThreshold()          │
└─────────────────┬───────────────────────────────────────────┘
                  ↓
┌─────────────────────────────────────────────────────────────┐
│                   Data Store Layer                           │
│  SettingsStore (持久化 - Room 数据库)                        │
│  - settings: Flow<AppSettings>                              │
│  - setR18SanityLevelThreshold(threshold: Int)               │
└─────────┬───────────────────────────────────────────────────┘
          ↓ (响应式订阅)
┌─────────────────────────────────────────────────────────────┐
│                   Cache Layer (新增)                         │
│  SettingsCache (内存缓存 - StateFlow)                        │
│  - r18SanityLevelThreshold: StateFlow<Int>                  │
│  - pixivLanguage: StateFlow<PixivLanguage>                  │
│  - getR18SanityLevelThreshold(): Int (同步访问)              │
│  - getPixivLanguageCode(): String (同步访问)                 │
└─────────┬───────────────────────────────────────────────────┘
          ↓ (读取)
┌─────────────────────────────────────────────────────────────┐
│                  Business Logic Layer                        │
│  - AgeLimitDeterminer.determine() - 使用 R18 阈值            │
│  - PixivApiClient - 使用 Pixiv 语言偏好                      │
│  - 其他需要高频访问配置的业务逻辑                              │
└─────────────────────────────────────────────────────────────┘
```

#### **步骤 5: 在 SettingsRepository 中添加接口和实现**

```kotlin
// 接口
interface SettingsRepository {
    suspend fun updateR18SanityLevelThreshold(threshold: Int)
    suspend fun updateMaxCacheSize(size: Int)
    suspend fun updateAutoPlayUgoira(enabled: Boolean)
}

// 实现
class SettingsRepositoryImpl(
    private val settingsStore: SettingsStore
) : SettingsRepository {
    override suspend fun updateR18SanityLevelThreshold(threshold: Int) {
        settingsStore.setR18SanityLevelThreshold(threshold)
    }
    
    override suspend fun updateMaxCacheSize(size: Int) {
        settingsStore.setMaxCacheSize(size)
    }
    
    override suspend fun updateAutoPlayUgoira(enabled: Boolean) {
        settingsStore.setAutoPlayUgoira(enabled)
    }
}
```

#### **步骤 6 (可选): 如果需要高频访问，在 SettingsCache 中添加缓存**

```kotlin
class SettingsCache(private val settingsStore: SettingsStore) {
    // 现有缓存...
    private val _r18SanityLevelThreshold = MutableStateFlow(6)
    val r18SanityLevelThreshold: StateFlow<Int> = _r18SanityLevelThreshold.asStateFlow()
    
    // 新增缓存（仅对高频访问的配置）
    private val _autoPlayUgoira = MutableStateFlow(true)
    val autoPlayUgoira: StateFlow<Boolean> = _autoPlayUgoira.asStateFlow()
    
    init {
        CoroutineScope(Dispatchers.Default).launch {
            settingsStore.settings.collect { settings ->
                _r18SanityLevelThreshold.value = settings.r18SanityLevelThreshold
                _autoPlayUgoira.value = settings.autoPlayUgoira
                // 其他缓存字段同步...
            }
        }
    }
    
    // 同步访问方法
    fun getR18SanityLevelThreshold(): Int = _r18SanityLevelThreshold.value
    fun getAutoPlayUgoira(): Boolean = _autoPlayUgoira.value
}
```

### 2. 何时使用 SettingsCache？

#### **需要缓存的情况** ✅

```kotlin

class AgeLimitDeterminer(private val settingsCache: SettingsCache) {
    fun determine(...): AgeLimit {
        val threshold = settingsCache.getR18SanityLevelThreshold() // 内存访问
        // ...
    }
}

// 2. API 请求时需要的配置
class PixivApiClient(private val settingsCache: SettingsCache) {
    fun request() {
        val language = settingsCache.getPixivLanguageCode() // 内存访问
        // ...
    }
}
```

#### **不需要缓存的情况** ❌

```kotlin
// 1. UI 层直接使用 Flow（自动响应式更新）
class SettingsViewModel(private val settingsRepository: SettingsRepository) {
    val settings: StateFlow<AppSettings> = settingsRepository.getSettings()
        .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5000), AppSettings.DEFAULT)

// 2. 低频访问的配置（只在特定场景使用）
class ExportManager(private val settingsRepository: SettingsRepository) {
    suspend fun export() {
        val settings = settingsRepository.getCurrentSettings() // 直接查询
        val exportFormat = settings.exportFormat
        // ...
    }
}
```

## 最佳实践总结

### ✅ DO (推荐做法)

1. **所有配置统一存储在 SettingsStore (Room 数据库)**
   - 单一数据源，易于管理
   - 支持事务和复杂查询

2. **高频访问的配置使用 SettingsCache 缓存**
   - 内存缓存，零延迟
   - 自动响应式更新

3. **UI 层直接使用 Repository 的 Flow**
   - 自动更新 UI
   - 不需要手动缓存

4. **配置更新通过 Repository → Store → Database**
   - 单向数据流
   - 易于追踪和调试

### ❌ DON'T (避免做法)

1. **不要在多处存储相同配置**
   - 避免数据不一致
   - 增加维护成本

2. **不要对低频访问配置使用缓存**
   - 增加内存占用
   - 增加代码复杂度

3. **不要在 UI 层使用 runBlocking 同步访问**
   - 阻塞主线程
   - 性能问题

4. **不要混用 DataStore 和 Room 存储同类配置**
   - 架构不一致
   - 难以维护

## 结论

**是否能都使用这样的结构？** ✅ **可以！**

统一框架的优势：
- ✅ 架构一致，易于理解和维护
- ✅ 性能优异，高频访问配置使用内存缓存
- ✅ 响应式更新，配置变更自动生效
- ✅ 扩展性强，新增配置项只需按流程添加
